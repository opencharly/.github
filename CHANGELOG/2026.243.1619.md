# 2026.243.1619 — fix(validator): arm auto-merge with gh pr merge <N> --repo <r> (owner/repo#N parses as a branch and never armed)

## Summary

Fixes two defects in the org-wide validation chain (`opencharly/.github`):

**1. Auto-merge arming bug (`pr-validator.yml`, 2 lines).** `gh pr merge --auto --squash "$REPO#$PR_NUMBER"` makes gh parse `owner/repo#N` as a **branch name**, so the `Enable auto-merge` step of the reusable workflow never actually armed a merge — every org landing has needed manual operator arming (proof in the run logs: `no pull requests found for branch "opencharly/opencharly#94"` across all 6 attempts on #94, and the same on #95). Fixed both invocations to the positional form gh accepts: `gh pr merge --auto --squash "$PR_NUMBER" --repo "$REPO"`, and `gh pr update-branch "$PR_NUMBER" --repo "$REPO"` in the behind-recovery path.

**2. Dangling dispatcher ref (`pr-validator-dispatcher.yml`, 1 line + comment).** The `.github` repo's own dispatcher pinned the reusable workflow at `@f0e1b9e1…` — the #82 self-gating SHA, which **diverges from `main`** (verified via compare API: `status: diverged`). GitHub's reusable-workflow expansion rules require the referenced ref to be the default branch or reachable from it, so every `.github` PR validator run died at startup (`startup_failure`, 0 jobs, empty `referenced_workflows`) and **no `.github` PR could get a verdict** — including this one, before the fix. Re-pinned to `@main`, which is byte-identical to the pin (`git diff` empty) and is the proven-working form every other org-repo dispatcher already uses (opencharly, charly, sdk, spec, marketplace, docs all use `@main`). This is the follow-up PR #82's body deferred.

## How tested

1. **Bug reproduction (the `main` form):**
```
$ gh pr merge --auto --squash "opencharly/opencharly#93" 2>&1
no pull requests found for branch "opencharly/opencharly#93"
```
2. **Fixed-form parsing (same host CLI):**
```
$ out=$(gh pr merge --auto --squash 95 --repo opencharly/opencharly 2>&1) && rc=0 || rc=$?; echo "rc=$rc"
rc=0
```
3. **Fixed shape proven live**: this exact form armed opencharly/opencharly#95 → native auto-merge merged it.
4. **Dispatcher expansion before/after:** with the dangling pin, PR runs died at expansion (0 jobs, `startup_failure` — runs 33410375516, 33412338301). After re-pinning `@main`, the PR-triggered run 33412516802 expanded into a real `validate / validate` job on head 34781a0.
5. **Pin equivalence:** `git diff <pr-validator.yml @ f0e1b9e1> <pr-validator.yml @ main>` is empty (byte-identical); compare API `main...f0e1b9e1` reports `diverged`.
6. **Org-wide R3 sweep (the buggy pattern exists nowhere else) — actual command + output:**
```
$ for repo in .github opencharly charly sdk spec marketplace docs; do cnt=$(gh api "repos/opencharly/$repo/contents/.github/workflows/pr-validator.yml" --jq .content 2>/dev/null | base64 -d 2>/dev/null | grep -c '$REPO#' || true); echo "$repo: $cnt"; done
.github: 2      # the two lines this PR fixes

```
