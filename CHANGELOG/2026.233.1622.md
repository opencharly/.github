## feat: auto-approve validator runs, remove dispatch step

### The change

1. **New `approve-validator-runs.yml`**: triggers on `workflow_run` of
   the pr-validator completing with `action_required`, and approves the
   run via the API. GITHUB_TOKEN pushes (CHANGELOG rename) create
   `pull_request: synchronize` runs in approval-required state; this
   workflow approves them automatically so the validator re-runs on the
   PR head without manual intervention.

2. **Remove the dispatch step** from the pr-validator: the approved
   `synchronize` run re-validates the PR head directly (with
   `pull_request` context), so the `workflow_dispatch` re-run is no
   longer needed.

### Why

Verified against GitHub docs: GITHUB_TOKEN pushes create
`pull_request: synchronize` runs in approval-required state. The
`workflow_dispatch` re-run creates a check on the dispatched branch's
head, not the PR head — so it doesn't satisfy branch protection. The
approved `synchronize` run creates a check on the PR head, which is
what auto-merge waits for.

### How tested

The flow will be exercised by this PR's own landing: validator passes →
CHANGELOG rename → GITHUB_TOKEN push creates action_required run →
approve-validator-runs approves it → validator re-runs on PR head →
auto-merge merges.
