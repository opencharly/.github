# 2026.242.2013 — fix(validator): resilient auto-merge arming

## Summary

Resilient auto-merge arming in the org validator composite: the `Enable auto-merge` step no longer fails the required check when arming races sibling checks.

- **RCA (live, plugin-mise#2):** the raw `enablePullRequestAutoMerge` mutation fired the moment the review verdict parsed — while the repo's `candy` CI check was still running. GitHub rejects the mutation with `Pull request is in unstable status` → unhandled throw → the **`validate / validate` check turned RED on a PASS verdict**, and the PR can never merge through the org flow.
- Repos with a single check (charly, sdk) never saw this because their validate is the only check; the comment "native auto-merge handles the ordering" implicitly assumed it.
- **Fix:** the arming step retries through transient states (unstable → wait; BEHIND → `update-branch` then retry), soft-skips with a warning if the repository setting disallows auto-merge, and NEVER fails the check on arming logistics (the review verdict already passed; a later dispatcher invocation can arm it).
