# 2026.314.0654 — fix(ci): the discovery count is a LOWER BOUND, not an equality

The discovery count invariant from `#291` was an **equality**, and a runner disproved it within hours. It is now a **lower bound**, which is the direction the failure actually takes.

## Summary

`.github` run **`42770802075`** (dispatch, `mode=verify`) died at discovery:

```console
discover_all: discovered 486 repo(s) but the org reports 485 — a page was TRUNCATED; refusing to understate the org
FATAL: discover_repos failed
```

The listing was right and the invariant was wrong. `public_repos + total_private_repos` is **not an exact census** of what the listing serves — it lagged by one — so an equality test turned a benign off-by-one into a hard failure of **every** org-wide script: exactly the class of failure the control exists to prevent.

| | Before | After |
|---|---|---|
| `discovered < reported` | abort | **abort** (truncation — unchanged) |
| `discovered == reported` | pass | pass |
| `discovered > reported` | **abort** | **pass** (the count lagged; the listing is authoritative) |

The suite carries both directions now, and the new one discriminates rather than decorating:

- the existing **truncation** case (`DISCOVERY_TRUNCATE=1`, listing one **fewer** than the count) still aborts;
- a new **over-count** case (`DISCOVERY_OVERCOUNT=1`, listing one **more** than the count) requires `verify` to succeed.

Mutation-proved: reverting the fix to `-ne` makes the new case fail with exactly its message —

