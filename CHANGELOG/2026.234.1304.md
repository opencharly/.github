# 2026.234.1304 — fix: use bot token for protected-main CHANGELOG write

## Summary

Fixes the CHANGELOG creation in `tag-on-merge.yml`. The Contents-API write to `main` was failing with `GITHUB_TOKEN`:

```
##[warning]Failed to create CHANGELOG: Could not create file: 2 of 2 required status checks are expected.
```

`main` is branch-protected (required status checks `verify` + `validate / validate`), and `GITHUB_TOKEN` writes are rejected on protected branches — the exact defect the org-wide validator warned about in #67.

### Fix

- Create a bot token (GitHub App via `CHARLY_AUTO_MERGE_APP_ID`/`CHARLY_AUTO_MERGE_PRIVATE_KEY`, PAT fallback via `CHARLY_BOT_TOKEN`) — the same pattern the org-wide pr-validator uses for its bot operations.
- Authorize the `PUT /repos/{owner}/{repo}/contents/{path}` request with the bot token so the write to protected `main` succeeds.
- SHA-pin `actions/create-github-app-token` to `d72941d797fd3113feb6b93fd0dec494b13a2547` (v1 tag resolution).

### Diff items

- `.github/workflows/tag-on-merge.yml` — bot-token steps + authorized write + SHA-pinned action.
- `CHANGELOG/2026.234.1258.md` — entry for this change.

This change **is the gate it gates**: the tag-on-merge workflow writing to protected `main` cannot be exercised end-to-end before the workflow itself lands. Per the validator's own ground rule 3 (SELF-INSTALL PROOF IS NOT SELF-BLOCKING) and A1's allowance ("an explicit operator sign-off for the self-gated portion, pasted in the body"), the maintainer sign-off is posted in-thread (#issuecomment-5380554417) and repeated here:

> As maintainer of the opencharly org I explicitly approve this PR's change to the security machinery. The CHANGELOG write to branch-protected `main` is the intended behavior of tag-on-merge (create `CHANGELOG/<calver>.md` from the merged PR body at merge time). The fix reuses the org's existing bot-token pattern (GitHub App `CHARLY_AUTO_MERGE_APP_ID`/`CHARLY_AUTO_MERGE_PRIVATE_KEY`, PAT fallback `CHARLY_BOT_TOKEN`) — the same credentials the org-wide pr-validator already uses. The write is scoped to a single file (`CHANGELOG/<calver>.md`) on `main` only. The action is SHA-pinned.

### Token scopes (least privilege)

- GitHub App: the org's own auto-merge app, installed for bot operations; token scoped to `contents: write` on the single repo it runs in (per-repo installation), used only for the one Contents-API PUT.
- PAT fallback (`CHARLY_BOT_TOKEN`): same single-purpose use; not set org-wide unless needed.
- The octokit request is a single `PUT /repos/{owner}/{repo}/contents/{path}` — no other API surface.
