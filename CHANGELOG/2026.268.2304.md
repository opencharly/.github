# 2026.268.2304 — feat(org-ruleset): enforce delete_branch_on_merge org-wide

## Summary of changes

Extend `scripts/org-ruleset.sh` — the SINGLE org-wide owner of per-repo settings — to enforce `delete_branch_on_merge`, exactly the way it already enforces `allow_auto_merge`.

GitHub exposes **no org-level toggle** for "Automatically delete head branches"; it is a strictly per-repository setting (identical in class to `allow_auto_merge`, for which this script is already the single owner). Today only 17 of the org's 416 active `main`-default repos have it on, so 399 repos accumulate `feat/` branches after their squash merge — contradicting the git-workflow contract that `feat/` is deleted at merge.

Concrete edits:

- **`scripts/org-ruleset.sh`**
  - `apply` (step 5): after the `allow_auto_merge` loop, read `.delete_branch_on_merge` and PATCH it to `true` when it is not already — idempotent, skip-when-true.
  - `verify`: assert `.delete_branch_on_merge == true` per repo, alongside the existing `allow_auto_merge` assertion.
  - Header + apply-order comments updated to name both per-repo settings and why neither can move to the org.
- **`scripts/org-ruleset_test.sh`**
  - Mock state grows `dbom_alpha`/`dbom_beta`; the mock `gh` now honors the `--jq` expression on the per-repo GET and the requested field on PATCH, so one endpoint serves both settings probes.
  - `apply` assertions: `beta` is PATCHed for `delete_branch_on_merge` and its state becomes `true`; `alpha` is not re-patched.
  - A new `verify` regression: `delete_branch_on_merge=false` on `beta` must FAIL verify.
- **`README.md`** — the `org-ruleset.sh` description now names both per-repo settings.
