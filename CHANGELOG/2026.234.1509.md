# 2026.234.1509 — fix: use raw fetch with bot token for CHANGELOG write

## Summary

Fixes the CHANGELOG write identity on protected `main`.

### Context

- The tag/CHANGELOG **decoupling** (independent idempotent tag + CHANGELOG creation) already landed on `main` via #70 — this PR does not re-introduce it.
- This PR (#71) contains exactly two diff items: the raw-`fetch` write fix in `tag-on-merge.yml` and its CHANGELOG entry.

### The fix

The ruleset `main-protection` (id 21198628) has the `charly-auto-merge` App (4675576) as the ONLY bypass actor for `main` (required checks `verify` + `validate / validate`, no force-push, no deletion, linear history — all preserved). But the write still failed:

```
Failed to create CHANGELOG: Repository rule violations found
2 of 2 required status checks are expected.
```

**Root cause:** `actions/github-script`'s octokit client is pre-authenticated with `GITHUB_TOKEN`. The per-request `headers.authorization` override is unreliable, so the request went out as `github-actions` — which is NOT a bypass actor for the ruleset — and the required-checks rule fired.

**Fix:** replace the octokit override with a raw `fetch()` that carries the bot token in the Authorization header, guaranteeing the request goes out as the App/PAT identity that IS the ruleset bypass actor.
