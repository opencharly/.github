# 2026.327.1411 — fix(arm): a CLEAN head is a report, not an arming failure

## Summary

Follow-up to **opencharly/.github#313**, measured on `opencharly/gst-wayland-display#12` once #314 had merged.

GitHub refuses `enablePullRequestAutoMerge` in **two** states, and only one is a fault:

| state | meaning | this gate's verdict |
|---|---|---|
| `unstable` | some check on the head did not pass | a finding — the poison #314 removed |
| `Pull request is in clean status` | every required check PASSED; the merge is available NOW; auto-merge has nothing to wait for | **not a finding** — the PR is ready |

The enable step treated every non-`unstable` error as a failure, so on a fully green PR it spent the whole 180 s budget retrying the one state in which arming is unnecessary, then threw — and #314's new report step posted an "Auto-merge was NOT armed" comment on a pull request that was simply ready to merge. Measured directly:

```
$ gh api graphql -f query='mutation { enablePullRequestAutoMerge(input: {pullRequestId: …, mergeMethod: SQUASH}) { … } }'
{"data":{"enablePullRequestAutoMerge":null},"errors":[{"type":"UNPROCESSABLE",
 "message":"Pull request Pull request is in clean status"}]}
```

The step now recognises that message, logs a notice that names the state and the remedy ("a maintainer merges this pull request") and returns: no retry, no thrown error, and therefore no unarmed-head comment — because nothing is unarmed. `Continue-on-error`, the green gate and the report step from #314 are unchanged.

**Every file in this diff, and what it does:**

| file | change |
|---|---|
| `.github/workflows/pr-validator.yml` | the recogniser in `Enable auto-merge` (one `if` + notice + return) |

| `scripts/arm-enable_test.sh` | the step-level test: extracts that script and runs it under node with mocked `github`/`context`/`core` (four assertions, one a negative control) |
