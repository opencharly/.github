### 1. Auto-close after N non-PASS verdicts (`BLOCK` **or** `INCONCLUSIVE`)

The auto-close step (`.github/workflows/pr-validator.yml`) was BLOCK-only. An INCONCLUSIVE run — the provider/engine produced no `Verdict:` line — grows the same runaway comment thread, so the loop is now bounded for **both** classes: the counter counts the validator's own `## Review — BLOCK` **and** `## validator INCONCLUSIVE` comments, the step is gated on `verdict == 'BLOCK' || verdict == 'INCONCLUSIVE'`, and the notice text distinguishes a code BLOCK from a policy bound (`0` disables it). Runs **before** the BLOCK/INCONCLUSIVE gates so the close + notice land, then the matching gate still fails the required check — the close is a policy action, not a verdict.

### 2. The INCONCLUSIVE notice no longer embeds the review-log diagnostics

A degenerate-repetition run carries hundreds of KB of noise (measured ~467 KB), and **this notice is re-ingested into the NEXT review's context** — embedding the runaway made the next review collapse harder (a positive feedback loop). The notice is now short and points at this run's **evidence artifact + job log** (neither of which a later review reads).

### 3. Harness coverage (the block-2 fix)

`.github/tests/validator-gate-harness.py` adds functional coverage that ties the auto-close counter to the gate's **emitted artifact**: the fake `gh api` replays the gate's real emitted notice, and a **negative control** proves a rename of the notice header drops the real counter to 0 (the guard is genuinely bound, not a text-counting tautology). `292 assertions / 18 scenarios`, ALL PASS on the final tree.

### 4. The harness is now self-cleaning (fixing its own RCA'd leak)

The environment RCA in the previous revision named an **in-tree** leak (not merely scratch): the `ensure-charly` pin-guard functional test downloads a ~383 MB pinned charly release into a `tempfile.mkdtemp` dir the harness never removed, so dirs accumulated across runs and exhausted the runner's quota (~30 runs → `EDQUOT`, after which **every** scenario fails with "Disk quota exceeded" and masquerades as a code regression). This revision fixes it **in-tree**: every harness temp dir is registered for removal at process exit, and an assertion fails if a created temp dir survives — so deleting the cleanup fails the harness (R1: the fix ships its own guard). Re-run after the fix: `created=2 leaked=[]`, zero dirs left on disk.
