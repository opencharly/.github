# 2026.270.0726 — docs(readme): new-repo setup + what the org/dotgithub automates vs what a repo adds

## Summary

Adds a **"Setting up a new repository — what is automatic, what you add"** section to the
README (the config owner's doc), so the new-repo procedure and the org/dotgithub
automation are unambiguous:

- a table splitting what the org/this repo does automatically (required validator, branch
  protection, native auto-merge, `delete_branch_on_merge`, CalVer tagging) from what a
  repo must add (the per-repo `.github/workflows/tag-on-merge.yml` caller + its own CI);
- a 5-step new-repo checklist (create non-fork → bootstrap `main` → add the caller →
  apply the org ruleset → land via PR → umbrella submodule + `task sync`);
- the by-design exclusions (forks, archived, non-`main` defaults);
- the measured gap (`layer-nerdctl`, `plugin-nerdctl` created with no `.github` at all →
  merge but never tag).

Docs-only change (README.md). Companion skill leg: `layer-charly-internals#28` (the new
`/charly-internals:repo-setup` skill).
