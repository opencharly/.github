# 2026.306.0155 — fix(ci): a re-run can clone over the previous attempt's checkout (#265)

## Summary

**The required `validate / validate` check now survives a re-run.** A re-run is the sanctioned
remedy for a failed or flaky check — and on a persistent self-hosted runner it *created* a
failure, because the previous attempt's clones were still sitting in the workspace root.

```
##[group]Run git clone --depth 1 --branch v0.2026305.1919 \
fatal: destination path 'contract' already exists and is not an empty directory.
##[error]Process completed with exit code 128.
```

Measured today on two re-runs, minutes apart, of heads whose diffs are unrelated to this step:

| PR | job | step | result |
|---|---|---|---|
| `opencharly/charly#1101` | `125050184101` | `Fetch the pinned contract` | exit 128 |
| `opencharly/charly#1100` | `125050180570` | `Fetch the pinned contract` | exit 128 |

…while `opencharly/charly#1102`, re-run within the same minute, cloned fine and went fully
green. That is the tell: it depends on **which runner picks the job**, not on the PR.

**Mechanism.** `contract/` and `org-rules/` are siblings of `repo/` in the workspace root, and
`actions/checkout` cleans only the directory it manages — the reusable workflow's own comment
already says exactly that about `runner-config/`. So attempt 1 leaves both clones behind,
attempt 2's `git clone` refuses a non-empty destination, and every later step — the sweep, the
review engine, `Parse verdict`, both gates — is skipped. The PR gets a red required check and
**no verdict at all**.

**Missed control.** Nothing asserted that a step which clones into the workspace root is
idempotent across attempts. These two steps are the only place in the job that writes a sibling
the checkout action does not own, and re-running is a documented remedy — so the remedy was
broken exactly where it was supposed to be used.

**Root fix.** Each fetch step clears its own destination before cloning (`rm -rf contract`,
`rm -rf org-rules`). The destination is this job's own, so the step becomes a function of its
inputs rather than of which runner picked the job. No fallback branch, no retry, no
suppression: the clone still fails loudly if the ref or the network is wrong — it just no
longer fails because of a file it wrote last time.

**Diff, every item accounted for:**

| File | Change |
|---|---|
| `.github/workflows/pr-validator.yml` | `rm -rf contract` and `rm -rf org-rules` before each clone, each with the mechanism and the measured job ids recorded beside it |
| `scripts/retired-sweep-arm_test.sh` | **case 7** extracts BOTH fetch steps and runs each over a pre-dirtied workspace, requiring the clone to succeed, the marker file to exist, and the previous attempt's file to be gone; **negative controls 6 and 7** strip each clear in turn and require the coverage to go RED for that step, so neither clear is passing because the fixture happened to be clean |

control 7 removes `rm -rf org-rules`; each re-runs the whole coverage against the mutated
workflow and requires it to go red **with that step's own failure text**, so neither control can
pass for the wrong reason.
