# 2026.273.0740 — fix(opencode)!: watcher — default events carry verdicts, every run status observed, ARM report on a pre-arm BLOCK

## Summary

**The OpenCode PR/issue watcher silently missed the things it exists to catch** — measured from the source. This is the four-part R1 defect (issue #323) plus a **pre-existing FATAL defect the live spike uncovered**.

All logic lands in the ONE shared engine `.opencode/lib/watch.ts`; the two bindings (`coord.ts`, `pr-watch.ts`) pass only their event defaults (R3 — no forked logic).

**The four parts, and the fix:**

1. **Defaults missed BLOCKs.** `coord.ts` `DEFAULT_EVENTS = "merged,closed,stall"` — a validator **BLOCK arrives as a COMMENT** and a completed run is a **VERDICT**; neither was in the default. `pr-watch.ts` `WATCH_EVENTS = "comment,merged,closed"` also omitted `verdict`.
   - `coord.ts`: `merged,closed,stall` → **`merged,closed,comment,verdict,stall`**
   - `pr-watch.ts`: `comment,merged,closed` → **`comment,merged,closed,verdict`**
2. **No run STATUS observed.** The query fetched `status conclusion` but kept **only `status === "completed"`** runs — a QUEUED/RUNNING run was invisible. Now the latest `charly/pr-validator` run is observed in **EVERY status** with status + conclusion, and `verdict` fires on a **run STATUS TRANSITION** (queued→running→completed), not only completion. Wake line:
   `VERDICT  owner/repo#12  charly/pr-validator  IN_PROGRESS  https://github.com/.../actions/runs/<id>`
   `VERDICT  owner/repo#12  charly/pr-validator  COMPLETED/success  ...`
3. **A pre-arm BLOCK/verdict was never surfaced** (delta seeding + a newness gate). Now the **ARM report** is the FIRST emission per item: the CURRENT baseline — latest run status+conclusion AND latest review comment's parsed verdict. Arming on an already-BLOCKed PR wakes immediately.
4. **Comment verdict was not read.** `comments { totalCount }` (count only) → `comments(last: 1) { totalCount nodes { body createdAt } }`; `parseReviewVerdict` reads the first non-blank line for `## Review — BLOCK` / `## Review — PASS` and carries it in the arm report and the `COMMENT` wake line.

**PRE-EXISTING FATAL defect (blocking, fixed here — R1/R2):** the batched GraphQL query selected `status`/`conclusion` on **`WorkflowRun`**, which are **NOT GraphQL fields** — every real fetch failed with `Field 'status' doesn't exist on type 'WorkflowRun'`. **The watcher had never worked live.** Status/conclusion now come from the `CheckSuite` (their real owner), verified against the live API (below).

**Constraints honoured:** event vocabulary unchanged (`merged|closed|comment|verdict|stall`; `verdict` semantics extended only); ONE batched GraphQL call per poll for N items; fingerprint skip extended (not weakened); rate-limit fail-hard unchanged. Both `.opencode/` copies (`opencharly` + `.github`) updated byte-identically (blob SHAs identical). **Plugins load once at startup — RESTART required to activate.**

Refs opencharly/opencharly#323 (the umbrella PR that carries the same change; the issue is closed by whichever lands first).
