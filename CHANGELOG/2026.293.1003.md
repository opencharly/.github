# 2026.293.1003 — ci(pr-validator): bound the `Ensure charly` step with a 15-minute timeout (#178)

## Summary

Adds `timeout-minutes: 15` to the `Ensure charly` step in `pr-validator.yml`. That is the whole diff: one YAML key plus a comment recording why it exists.

**The defect (`opencharly/.github#178`).** The step can hang indefinitely. When it does, the job never concludes, so the `charly/pr-validator` check-run stays `in_progress`, so native auto-merge never arms — and the PR is wedged with the validator's verdict already posted and green.

**Measured cost, twice in one session:**

| PR | symptom |
|---|---|
| `opencharly/marketplace#503` | 5 PASS verdicts on an unchanged head; `charly/pr-validator` and `build` both `in_progress` with `updated_at` frozen for minutes; `mergeable_state=blocked`, `armed=n`. It landed only after the run was finally reaped. |
| `opencharly/docs#166` | `validate` failed a second time **without posting a verdict and with an empty `--log-failed`** — a concluded-but-empty failure with nothing to read. |

**What was tried and did not work** (so the fix is not mistaken for a re-run tip): `gh run rerun <id> --failed` and `POST /check-runs/<id>/rerequest` both return **404** on these repos. A push cancels the stuck run (3/3). `gh pr close` + `gh pr reopen` reaps without a new commit, leaving the head unchanged — that is recorded on `#178` with evidence. Every reap produced another run that could hang identically; only a bound on the step ends the class.

## How tested

The workflow file is parsed and the key is asserted on the step that carries the id, not eyeballed:

```console
$ python3 -c "import yaml; yaml.safe_load(open('.github/workflows/pr-validator.yml'))"
YAML parses: ok
$ python3 -c "import yaml; d=yaml.safe_load(open('.github/workflows/pr-validator.yml')); print([s.get('timeout-minutes') for j in d['jobs'].values() for s in j.get('steps',[]) if s.get('id')=='ensure-charly'])"
step timeout-minutes: 15
```

`timeout-minutes` on a step is a documented GitHub Actions primitive: on expiry the step fails, the job concludes, and a conclusion is what posts the check-run result — which is exactly the behaviour that is missing today. The 15 minutes is generous against a binary download and deliberately short of the ~6-hour job default.
