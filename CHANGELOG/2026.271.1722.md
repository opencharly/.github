# 2026.271.1722 — fix(org-ci): never abort the candy-gate retirement wave on one repo

## Summary

The org-wide candy-gate retirement (`scripts/retire-per-repo-candy-gates.sh`) **aborted the entire ~300-repo wave on one repo**. Run `36455597712` died at:

```
FATAL: layer-camsnap deploy.yml metadata fetch failed — refusing to read it as 'not the candy stub'
```

**RCA (executed).** `stub_meta()` returned non-zero on *any* fetch/decode failure and the caller turned that into `exit 1`. `layer-camsnap`'s `deploy.yml` was **already deleted** by commit `3257d87` (`2026-09-28T17:05:37Z`), authored by the **concurrent run `36455573679`** (dispatched 17:04:40, i.e. 13s before the failing run `36455597712` at 17:04:53). The failing run's `api_status` probe of `layer-camsnap` returned **200**; its `stub_meta` fetch one second later returned **404**:

```
$ gh api repos/opencharly/layer-camsnap/contents/.github/workflows/deploy.yml
{"message":"Not Found","documentation_url":"…","status":"404"}   # exit 1
$ git -C layer-camsnap show -s --format='%ci' 3257d87
2026-09-28 17:05:37 +0000
```

So the trigger is a **probe→fetch 404 race between two concurrent runs of this same wave** — a case the pre-fix script could not tell apart from a real failure. (Two runs in flight, `36455573679` `in_progress` + `36455597712` `failure`; a third earlier one `36454414844` also failed the same way.)

## Fix

`stub_meta()` now **always returns 0** and prints a leading status; the caller branches:

| status | meaning | action |
|---|---|---|
| `ok` | blob metadata + text read and classified | unchanged `name: candy` **AND** `charly box validate` safety gate; eligible for delete |
| `vanished` (HTTP 404) | deleted between the probe and this fetch by a **concurrent run** of this wave | counted `absent`, **never failed**, never deleted — idempotent |
| `failed` | transient/technical fetch or decode error | recorded in a distinct `failed` counter + `FAILED repos` list, **logged loudly**, **never deleted**, **loop continues**; the run exits non-zero so it is never silent |

1. **Fail loud, per-repo — never abort the wave.** A technical failure increments `failed` and the loop proceeds; `MAX_FAILURES` still guards a genuinely broken token/endpoint (`failed > MAX_FAILURES` aborts).
2. **Large-file case.** When the Contents API omits inline `.content` (blobs > 1 MB, `.encoding: "none"`), the script falls back to the git blob API (`repos/$ORG/$repo/git/blobs/$sha`) to read the text — so a big `deploy.yml` is **classified, not failed**.
3. **The fail-closed SAFETY gate is unchanged.** Deletion still requires **both** `name: candy` **and** the `charly box validate` signature; a mismatch is skipped, never touched.
4. **Probe failures still abort.** A non-404 `api_status` failure remains FATAL (a probe transport failure must never read as "absent" org-wide).
