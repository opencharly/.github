## RCA

- **Mechanism.** `runc` chooses its state root from its **effective** uid. rootlesskit maps this user to uid 0 inside its user namespace, so `runc` believes it is root and takes its **rootful** default state root, `/run/runc`. On the runner that path exists, is root-owned, and is not traversable by this user — so `lstat` on the per-container directory fails before the process starts. `buildkitd` has no flag for it (verified: `buildkitd --help` at `v0.34.1` has no `runc-root`, and `/run/runc` does not occur in the binary, so the value is `runc`'s own default).
- **Missed control.** *Ensure the builder* already established `/run/buildkit` for exactly this class — a rootless daemon blocked on a root-owned host path — but only that one path, and nothing asserted the **runc** state root. Because the old engine discarded the step's stderr, every run reported the same uninformative `exit code: 1`.
- **Blast radius.** Every `charly box build` in this workflow, on any repo: **no image could ever be built here**, so W5.4's twelve `pod-crabbox*` images could not be produced.
- **Root fix.** Both host paths now go through **one loop over one predicate**, so they cannot drift into divergent ownership rules:

```yaml
for d in /run/buildkit /run/runc; do
  sudo mkdir -p "$d"
  sudo chown "$(id -u):$(id -g)" "$d"
  test -w "$d" || { echo "::error::$d is not writable by $(id -un); the build cannot start"; exit 1; }
done
```

Each path's own measured evidence is kept in the comment above the loop. Never a blanket `chown`: each path is created and owned individually, and root keeps full access, so a rootful runc elsewhere on the runner is unaffected.
