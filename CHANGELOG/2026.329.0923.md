# 2026.329.0923 — feat(fork-gate)!: gate every first-party fork with the org ruleset, no copied caller

## Summary

Measured 2026-11-25 (issue #320): the org has **20 active forks**, and the org-wide gate
covered none of them. This cutover gates every fork with the SAME org required workflow —
**no `pr-validator.yml` caller is copied into any fork**.

- **One spec, two org rulesets.** `scripts/org-ruleset.sh` now builds ruleset A (active
  non-fork `main`-default repos) and ruleset B (the active forks, `~DEFAULT_BRANCH`) from
  ONE payload builder. Both carry the `workflows` rule (the org required workflow), the
  strict required `validate / validate`, `non_fast_forward`/`deletion`/`creation`, and the
  charly-auto-merge App bypass. A fork's check is produced by the org workflow.
- **Fork settings first.** `allow_auto_merge`, `delete_branch_on_merge` and
  `allow_update_branch=false` over `discover_forks`, **before** the gate exists, so a PASS
  can arm (#212: with auto-merge disabled an approved PR renders as a FAILED check).
- **Duplicate-producer guard + cleanup.** `apply` refuses while a fork still carries a
  `pr-validator.yml`; it deletes every fork's non-canonical BRANCH repo ruleset
  (`crabbox PR gate`, gst's `main branch protection`, Qwen3-TTS's workflows-rule ruleset),
  KEEPS tag-target rulesets, FATALs on an unclassifiable target, and removes legacy
  protection on the fork's DEFAULT branch (`stable`/`master` included).
- **Verify closes #225 for the fork set.** One shared assertion set judges A and B; the
  fork loop asserts the default branch, no repo branch ruleset, the tag caller, the
  settings and legacy protection; archived forks are named, never silently skipped.
- **Tag caller on forks.** `retire-per-repo-dispatchers.sh` and
  `reconcile-tag-on-merge-callers.sh` gain `SCOPE=forks`. The canonical caller is installed
  on the fork's DEFAULT branch as a BIRTH (untagged — design-pintag's
  `pre-release-process`), a copy that pins the reusable to a SHA is bumped to the CURRENT
  `.github` main sha, and the targets scope still never installs an absent caller.
- **Two real bugs fixed.** `tag-on-merge.yml` hard-coded `main` for the CHANGELOG
  read/write, so a `stable`/`master` fork would mint a tag and write no CHANGELOG → now
  `pr.base.ref`. The dispatcher's `push` backstop covered only `main` → now
  `main`/`master`/`stable`.
- **Mirror sync.** The `workflows` rule blocks a USER-token `gh repo sync` (#179), so a new
  `sync-forks.yml` fast-forwards with the App token (the ruleset's bypass actor). It never
  forces: a conflict is reported and fails the run.
- **Legacy deleted (R5).** `templates/fork-pr-validator.yml` is removed; no fork validator
  caller remains.
