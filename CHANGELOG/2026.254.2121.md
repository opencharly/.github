### 2. T3/T4 — the guardrail no longer fails closed on a non-zero review exit (FIXED IN THE TREE)

**The defect, exactly as reported.** `charly review ... || rc=$?` captured the exit code but nothing gated on it: a review exiting non-zero that had written a PASS line into `/tmp/review.txt` set `success=true`, Parse verdict read `PASS`, and **Enable auto-merge armed** — job exit 0. On `main` the same case failed the required check (`bash -e` aborted the step). Removing a fail-closed condition from the guardrail was the finding, and it was right.

**The fix — a non-zero review exit may only yield BLOCK or INCONCLUSIVE; PASS requires exit 0. TWO layers:**

*Layer 1 — the review step discards an untrusted verdict* (`.github/workflows/pr-validator.yml`, review step):

```bash
# FAIL-CLOSED on the review exit code (T3/T4): capturing rc must
# never mean WEAKER than the bash -e it replaced. ...
discarded=false
if [ -n "$verdict" ] && [ "$rc" -ne 0 ] &&
   [ "$verdict" != "BLOCK" ]; then
  discarded=true
  untrusted=$(printf '%s' "$verdict" | tr '\n' '+')
  echo "::warning::review rc=$rc wrote $untrusted — FAIL-CLOSED"
  echo "  discarded: a non-zero review exit may only carry BLOCK"
  mv /tmp/review.txt /tmp/review.untrusted.txt
  verdict=""
fi
```

The file is MOVED ASIDE, so the downstream Parse-verdict step cannot see it. `success=false`, `inconclusive=true`, `discarded_verdict=true`; `success=true`/`verdict=PASS` are emitted ONLY when a verdict survived (i.e. exit 0, or a BLOCK from a non-zero run — a finding is a finding).

*Layer 2 — Parse verdict is its own fail-closed gate* (`env: REVIEW_RC` = `steps.review.outputs.review_rc`), so a verdict that somehow survives still cannot become PASS from a non-zero review:

```bash
if [ "${REVIEW_RC:-0}" != "0" ] && [ "$distinct" != "BLOCK" ]; then
  echo "verdict=INCONCLUSIVE" >> "$GITHUB_OUTPUT"
  echo "::warning::review rc=${REVIEW_RC}, verdict not BLOCK"
  echo "  FAIL-CLOSED: a non-zero review exit may only carry BLOCK"
  exit 0
fi
```

*Layer 3 (reporting)* — `Gate (inconclusive)` names the discarded-verdict class instead of the generic verdict-less one: `class="charly review exited rc=${REVIEW_RC} with a non-BLOCK verdict — FAIL-CLOSED: a non-zero review exit may only carry a real BLOCK finding, discarded"`.

**Proven, not asserted — the negative discriminator.** The SAME v4 harness driven against the PRE-FIX workflow (#94's head file) **FAILS**: `scenario pass-with-error: job exit 0 == expected 3`, `classified verdict 'PASS' == expected 'INCONCLUSIVE'`, `auto-merge armed (True) == expected False`, with the transcript showing `[Enable auto-merge] exit 0 / Auto-merge armed`. On this tree the scenario yields **`job exit 3`** and `auto-merge armed (False)`. Both runs are pasted below.
