# 2026.314.2006 — fix(ci): name an exhausted API quota once, at every read and at the create

## Summary

`opencharly/.github#300`. The fleet run of `scripts/backfill-missing-tags.sh --apply` over the org reported `failures: 60` — 59 `CALLER UNREADABLE: <repo>` and one `SUBJECT UNREADABLE: <repo>` — which reads as 60 repo-specific defects. **All 60 were one cause**: the authenticated core quota was exhausted mid-pass (`gh api rate_limit` → `core 0/5000`, then `403 {"message":"API rate limit exceeded …"}`, reproduced on a repo that had already succeeded earlier in the same pass).

`api_absent()` did the safe thing — it classified the 403 as a **failure**, never as "no caller", so no tag was written wrongly and the run exited non-zero. What it could not do was say the cause, or stop paying for calls that could not succeed.

**What this does** (2 files, +242 −35):

1. **One classifier.** `classify_api_error()` answers 404 = absent, a spent quota = refused, anything else = failure. `api_absent()`, the subject read, the parent read and the create all call it, so the predicate exists once.
2. **One bookkeeping path.** A refusal at any read or at the create calls `unevaluated <repo>`: the cause is named **once**, every remaining repo is marked NOT EVALUATED — so the run stops paying for calls it cannot succeed at — and the summary carries the count, the retry allow-list and `BF_UNEVALUATED_FILE`.
3. **The safety behaviour is untouched.** Add-only, the per-repo CalVer form, the explained-head skip and the point-read identity checks all behave exactly as before.

## Scope — narrower than the PRs this replaces, and that is deliberate

`#301` and `#302` were **auto-closed by the validator** at five counting verdicts each (`AI_REVIEW_AUTO_CLOSE_AFTER=5`). Their tail had one cause that was mine, not the validator's: they also changed a **generic API read failure from ABORT to CONTINUE**, which `#300` never asked for. That turned one new answer into a `rc=2` branch at every call site, and each of those was a new behaviour that rightly demanded an arm.

**This change removes it.** A read that fails for a reason other than 404 or a spent quota aborts exactly as it did before, and the one new answer is the quota class. The 19 arms below cover every refusal site — caller, head, tags listing, second (parent) tags listing, confirming ref, 422-path ref, subject, parent, create — and nothing else changed.
