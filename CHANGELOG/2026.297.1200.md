# 2026.297.1200 — fix(gate): the governance manifest must assert against surfaces that exist (#246)

## Summary

The org's cross-surface governance manifest — `scripts/governance-claims.tsv`, the file that makes a rule's presence across the umbrella rulebook, the authored skill sources, the generated marketplace corpus and the validator rulebook **non-silent** — still pointed **19 of its 81 rows** at two files that no longer hold the skill prose, and **nothing asserted the manifest's own paths**, so a surface that moved was indistinguishable from one that was never checked.

Three things change:

- **The 19 rows are repointed** at the authored homes, where the prose actually lives since AGENTS.md Part II #5 moved it out of the candy manifests: `layer-charly-internals/.agents/skills/git-workflow/SKILL.md`, `layer-charly-internals/.agents/skills/git-workflow/references/multi-repo-coordination.md`, `layer-charly-internals/.agents/skills/cutover-policy/SKILL.md` and `layer-charly-internals-extra/.agents/skills/strict-policy/SKILL.md`. **12** of the 19 were a **false red** (a `require` row asserting a phrase the file does not carry); the other **7** were `forbid` rows that **passed vacuously** — the retired phrase was absent from a file that held no rule at all. 23 % of the manifest protected nothing.
- **One anchor is re-anchored and one row is added.** `BLOCKS. on BOTH threads` exists nowhere in the org; the authored source says `HOLDING` on BOTH threads, and the umbrella's own rulebook says `HOLDING` if you are the blocking side. Each is now asserted, each with its own anchor.
- **A named surface must also EXIST.** A surface whose **owner repo is materialized** in this checkout but whose **file is absent** is a **STALE POINTER** and now **FAILS**. Before this change it was silently downgraded to *"not checked"* — and that silent downgrade is exactly how 19 of 81 rows protected nothing while the gate looked green. A skip stays right for a surface this checkout does not carry at all: an uncarried owner repo, or an **uninitialized (empty) submodule path** in a light checkout, which must not become a false red. A bare path is judged only in an **umbrella** root (the `dotgithub/` mount) — the same discriminator the path resolver uses — so a standalone `.github` checkout that merely has a directory sharing a sibling's name cannot produce a false red either.
