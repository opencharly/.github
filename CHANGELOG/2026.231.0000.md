# 2026.231.0000 — org-wide automated PR validation (pr-validator + gate)

## Added — org-wide `charly/pr-validator` workflow

- **`.github/workflows/pr-validator.yml`** — replaced the manual, agent-posted
  `charly/pr-validator` commit status with an actual GitHub Actions workflow that
  runs the [`shaftoe/pi-coding-agent-action`](https://github.com/shaftoe/pi-coding-agent-action)
  as a fresh, independent PR validator on every non-fork pull request in the
  org. The job is named `charly/pr-validator`, so its check run satisfies the
  org-wide branch-protection required context of that name.
- **Fully generic — no credential, model choice, or provider endpoint is hardcoded.**
  `provider`/`model`/`base_url` come from
  org variables and the API key from the `AI_REVIEW_API_KEY` org secret; pi
  resolves the model in its built-in provider catalog, sets the key via
  `setRuntimeApiKey()`, and overrides the endpoint via `registerProvider()`. No
  `models.json` is written.
- **Single comment, no duplication.** The action natively posts the agent's
  response (success and failure); no separate `gh pr comment` step.
- **Re-run capable.** The validator runs with `bash`/`read`/`find`/`grep` over
  the checked-out repo, so git sweeps (per submodule), YAML/JSON validation,
  generator regeneration checks, and available lint/vet/test gates are genuinely
  re-executed at the PR head — never author-trusted.
- **Gate.** The verdict step (`exit 0` PASS / `exit 1` BLOCK / `exit 2`
  infra-or-no-verdict) always runs so the check state is set even on infra
  failure.
- **Strict PR-template compliance** is a hard gate; **`Assisted-by`** is
  deterministic (`Assisted-by: Nobody` for human-only work).
- **`README.md`** — documented the workflow, its required org-level config, and
  the honest capability scope.

## Notes

- **Evidence baseline (honest capability scope).** The validator re-runs with bash
  everything that is locally re-runnable at the PR head. Live external-bed
  re-runs — `charly check run <bed>` on a disposable target, VM/container/lab
  probes — cannot run inside the Actions runner; those are verified from the
  author's pasted output with an explicit tool-limited disposition (see README
  "Scope & evidence baseline"). Deep independent bed re-execution remains the
  shell-enabled fresh-evaluator agent's job in the `charly` repo.
- **Structural merge-order gate.** The gate's PASS path stays red until the
  companion cut-over (`opencharly/charly` #349, `opencharly/plugins` #213) has
  actually merged (removing the agent-side posting), so there is never a dual
  writer to the required `charly/pr-validator` context. Permanently green after
  the companions land.
- **Operator bootstrap exception (self-install).** Because a gate cannot approve
  the PR that installs it, the operator signed the bootstrap exception (recorded
  in PR thread comment): the gate-only installing PR is merged by the operator
  once the validator returns PASS; the install-check on that head is red by
  design until the companions land, after which this check is permanently green.
