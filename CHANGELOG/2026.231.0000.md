# 2026.231.0000 — org-wide automated PR validation (pr-validator + gate)

## Added — org-wide `charly/pr-validator` workflow

- **`.github/workflows/pr-validator.yml`** — replaced the manual, agent-posted
  `charly/pr-validator` commit status with an actual GitHub Actions workflow that
  runs our own [`opencharly/pi-review-action`](https://github.com/opencharly/pi-review-action)
  as a fresh, independent PR validator on every non-fork pull request in the
  org. The job is named `charly/pr-validator`, so its check run satisfies the
  org-wide branch-protection required context of that name.
- **Fully generic — no credential, model choice, or provider endpoint is hardcoded.**
  `provider`/`model`/`base_url` come from org variables and the API key from the
  `AI_REVIEW_API_KEY` org secret; the model id is passed **verbatim** to the provider's
  chat-completions endpoint (`~deepseek/deepseek-v4-flash-latest` is OpenRouter's own
  latest-alias id, per its public `/models` catalog). No `models.json` is written and no
  prompt is duplicated in the workflow.
- **The validator prompt lives in the action** (`opencharly/pi-review-action@v1.0.0`'s
  `prompt.txt`), not the workflow — single source, reusable across every inheriting repo.
- **Single comment, no duplication.** The action natively posts the agent's
  response (success and failure); no separate `gh pr comment` step.
- **Read-only, static gate.** The validator runs with five read-only GitHub
  tools (`get_pr_diff`, `get_pr_commits`, `get_pr_thread` where the CURRENT live issue is
  text-authoritative, `get_pr_meta`, `get_ci_status`) — no shell. It derives what it can from the diff/commits/thread/CI/logs
  and cross-checks pasted evidence for internal consistency with explicit tool-limited
  dispositions; it never fabricates a run. Deep bed re-execution remains the landed
  `charly` fresh-evaluator agent's job.
- **Gate.** The verdict step (`exit 0` PASS / `exit 1` BLOCK / `exit 2`
  infra-or-no-verdict) always runs so the check state is set even on infra
  failure.
- **Strict PR-template compliance** is a hard gate; **`Assisted-by`** is
  deterministic (`Assisted-by: Nobody` for human-only work).
- **`README.md`** — documented the workflow, its required org-level config, and
  the honest capability scope.

## Notes

- **Evidence baseline (honest capability scope).** The validator is a read-only
  static gate (five read-only GitHub tools — get_pr_diff, get_pr_commits,
  get_pr_thread, get_pr_meta, get_ci_status — no shell). It cannot re-run beds, generators,
  greps, or lint in the runner; those are verified from the author's pasted
  output with an explicit tool-limited disposition (see README "Scope &
  evidence baseline"). Deep independent execution remains the shell-enabled
  fresh-evaluator agent's job in the `charly` repo.
- **Single writer, no cross-repo gate.** The required `charly/pr-validator`
  context is set by this workflow — the canonical writer in every repo that
  installs the dispatcher — and branch protection enforces it. No hard cross-repo
  merge-order dependency: an earlier design stalled companion PRs on a gate that
  only becomes satisfiable after this install lands (a self-install deadlock),
  so companion merges are sequenced by the operator, not by a hard gate.
- **Self-install, no blocked green.** The end-to-end green check of a self-gated
  install is not observable before the gate merges. The validator guidance
  (and README) therefore never treats that as a blocking finding: it verifies the
  mechanism statically, accepts an explicit operator sign-off, and passes unless
  a genuinely fixable, non-self-blocking defect remains.
- **Prior-comment staleness check (R1).** get_pr_thread returns the live
  body plus every accumulated comment; earlier `github-actions[bot]` reviews are
  not authoritative and are often stale. The validator guidance now mandates
  re-deriving every claim it would rely on from the CURRENT live body + CURRENT
  diff and dismissing prior-comment assertions that no longer match as
  stale/superseded — a finding survives only if it reproduces against the current
  state. This fixes the confluence where the validator imported old reviewers'
  claims (an old head SHA, an old file count) into each new review instead of
  verifying against the live state.
- **Interval reconstruction (changes since the last validation).** The validator
  guidance now directs it to fully understand what changed since the last
  validation comment by reading the authoritative CURRENT full diff and
  reconstructing the delta against what prior comments described — the review must
  describe the code as the current diff shows it, never as an earlier comment did.
  The interval-reconstruction direction stands (the review must describe the code as
  the current diff shows it), but the validator now has a `get_pr_commits` tool that
  returns the PR's commit history (sha/message/author) — so commit-level claims are
  read directly from that tool plus the current diff, never from a prior comment's
  summary.
