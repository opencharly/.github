# 2026.267.2031 — fix(validator): enforce the charly pin — never run a stale engine

## Summary

Enforce the org `CHARLY_VERSION` pin in the review gate's `ensure-charly` step, so the gate can never silently run a **stale** engine.

### Root cause (measured)

The gate's review engine is not a service — it is whatever `plugin-review` is **welded into the charly binary**. The runaway/empty-completion defect was already fixed (the tool loop was deleted in `plugin-review v2026.264.1425`), yet the gate kept returning **no verdict** (INCONCLUSIVE, check RED). The engine the gate actually ran was stale:

| charly binary | welded `plugin-review` | tool-loop engine? |
|---|---|---|
| org pin `vars.CHARLY_VERSION=v2026.267.0045` | `v2026.266.1944` | **no** — fixed |
| self-hosted runner image (`/usr/bin/charly 2026.256.1316`) | `v2026.255.1648` | **yes** — pre-fix |

The failing run's log carried `pass 1/1`, `turn 1: 4 tool call(s)`, `turn 2: final content len=0` and `failed to produce a Verdict line`. Those strings exist **only** in the ≤`v2026.263.x` engine (removed in `v2026.264.1425`) — verified by `strings` against both the pinned release binary and `plugin-review@main` (the pinned one carries the fixed engine's marker, `there is nothing to fetch`; neither carries the tool-loop strings).

The mechanism is the `ensure-charly` short-circuit:

```bash
if command -v charly >/dev/null 2>&1; then
  echo "charly present: $(charly version)"; exit 0   # trusts ANY on-PATH charly
fi
```

On a self-hosted runner whose image bakes an old charly (`REVIEW_RUNNER_LABEL=opencharly`, set 2026-09-24T13:26Z), the pin was **never** downloaded and the stale welded engine ran. The gate's earlier PASSes were on `ubuntu-latest` (no charly on PATH → the pin was downloaded → the fixed engine).

### The fix

`ensure-charly` now:
1. **Refuses to run without the pin** — an unset/repo-invisible `vars.CHARLY_VERSION` is a loud `::error::` + `exit 3` (the INCONCLUSIVE class; never a silent fallback to a bundled engine).
2. **Uses an on-PATH charly ONLY when its version equals the pin** (`charly version` → the CalVer, compared to `${TAG#v}`).
3. **Otherwise warns loudly and downloads + prepends the pinned release**, so the pinned engine always wins.

`.github/tests/validator-gate-harness.py` gains **4 structural + 3 functional** assertions (the functional ones execute the real step body against a controlled PATH): pin unset → `exit 3`; on-PATH == pin → use it; on-PATH != pin → `::warning::` + download.
