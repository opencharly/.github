# 2026.265.1826 — feat(ci): bootstrap the initial main on empty org repos

## Summary of changes

The org-wide ruleset (`#109`) carries the `creation` rule on `refs/heads/main`, so a **brand-new repo cannot create its first `main` by any operator path**. Measured on the three repos created *after* the ruleset landed:

```console
$ git push -u origin main
remote: error: GH013: Repository rule violations found for refs/heads/main.
remote: - Cannot create ref due to creations being restricted.
# contents API, repo WITH other refs but no main (branch=main):
$ gh api -X PUT repos/opencharly/pod-qdrant/contents/README.md ... -f branch=main
{"message":"Branch main not found", ... 404}
# contents API, repo with NO refs at all (with or without branch=main):
$ gh api -X PUT repos/opencharly/zz-test-bootstrap2/contents/README.md ...
{"message":"Repository rule violations found ... Cannot create ref due to creations being restricted.", status 409}
$ gh api -X POST repos/opencharly/<repo>/branches/<b>/rename -f new_name=main
{"message":"Validation Failed","errors":["repository rules do not permit renaming branch '<b>' to 'main'"]}
# repo auto_init: the repo's own initial commit is ALSO blocked; repo stays empty.
$ gh repo list opencharly --limit 1000 --json name,createdAt,defaultBranchRef \
    --jq '[.[]|select(.createdAt > "2026-09-22T14:11:00Z")]|.[]|"\(.name) main=\(.defaultBranchRef.name)"'
plugin-qdrant main=        # no repo created after the ruleset has a main ref
pod-qdrant    main=
layer-qdrant  main=
```

The ruleset's only bypass actor is the `charly-auto-merge` App, and a repo with no `main` cannot produce the required `validate / validate` check (the required workflow does not exist on the default branch) — a genuine deadlock reached from a clean start.

This PR adds the missing bootstrap, in the same shape the org already uses for `retire-per-repo-dispatchers` (an App-token workflow for a write an operator token may not make):

- **`scripts/bootstrap-repo-main.sh`** — creates `refs/heads/main` from the repo's current default-branch HEAD via `POST /git/refs` (the git-data API has **no branch-must-exist precondition**; the contents API does). It **never** moves an existing `main` (skipped), skips a repo with no non-main ref to seed from, and is idempotent. `GH_TOKEN` is required; a repo-discovery failure aborts.
- **`scripts/bootstrap-repo-main_test.sh`** — the offline mock-`gh` test (the repo's established pattern), covering: seed from the default `feat/x`, seed from a non-main default, skip-already-has-main, skip-nothing-to-seed, idempotent re-run, explicit-repo targeting, discovery-failure abort, and missing-`GH_TOKEN` abort.
- **`.github/workflows/bootstrap-repo-main.yml`** — mints the `charly-auto-merge` App token and runs the script (optionally scoped to named repos). Needs only the App's existing `contents: write`; no `workflows: write`.
  - **Threat model / input safety:** the `repos` `workflow_dispatch` input is passed through the **environment** (`env: REPOS`) and expanded **quoted** (`read -ra targets <<<"$REPOS"; "${targets[@]}"`), never interpolated into the `run:` body. Raw `${{ inputs.repos }}` inside `run:` is unsanitized, and this step holds the org-wide App token (the ruleset bypass credential), so an injected `x; <cmd>` would be a real escalation — the quoted-env form removes the injection. The input only ever reaches the script as **repo-name arguments**, and the script resolves each name against the org (`repos/$ORG/$repo`); it never `eval`s an argument. `workflow_dispatch` already requires write access.
- **`README.md`** — documents the gap, the measured evidence, and the two-command bootstrap (App creates the ref; the operator sets the default branch with an admin token).
- **`.github/workflows/validator-harness.yml`** — runs the new offline test on every PR.

**Closes / relates to:** closes opencharly/.github#111. Follow-up to #109 (the ruleset that introduced the `creation` rule) and #110 (the App-token precedent).

**Breaking change + rollback:** none — purely additive (a new script, its test, a workflow, and README prose). Rollback = revert this commit.
