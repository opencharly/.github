# 2026.281.0840 — fix(validator): gate on same-repo, not on the repo being a fork

## Summary of changes

Correct the org-required workflow's `validate` job predicate. It gated on
`github.event.pull_request.head.repo.fork == false` — *"is the head repo itself a
fork?"* — which is **true for every PR in a first-party fork repo**. opencharly
vendors several upstreams as forks (`dsh-github`, `crabbox`, the `pi-*` family), so
the org's **own same-repo PRs were skipped**, and the ruleset's REQUIRED
`validate / validate` check was never produced. Such a PR could never merge.

The fix gates on the correct predicate:
`github.event.pull_request.head.repo.full_name == github.repository` — the head repo
is a *different* repository than the base. Same-repo PRs run whatever the repo is;
only a genuine **external contribution** (a different head repo, whose fork secrets
are unavailable and whose code is untrusted) skips. A null head repo (a deleted fork)
resolves to `'' != github.repository`, so it skips — the safe default.

Files:

- `.github/workflows/org-wide-pr-validator-required.yml` — the `if:` predicate on the
  `validate` job, plus a header comment recording the root cause and the measured
  evidence.
- `.github/tests/validator-gate-harness.py` — a `job_if()` reader and five assertions
  (presence + the three-case truth table + the forbidden retired predicate).
- `scripts/governance-claims.tsv` — a `same_repo_gate` claim: require the new
  predicate, forbid an ACTIVE `if: ... head.repo.fork == false` line.
- `README.md` — a "The gate runs on SAME-REPO PRs, whatever the repo is" subsection.

## Root cause (R1, measured 2026-10-07)

The org ruleset (ONE, `scripts/org-ruleset.sh`) targets `~ALL` repos **minus** an
explicit exclude set. `discover_excludes` filters on `isFork == true`, so forks are
excluded **by design** — but the exclude list is only re-derived on `apply`, last run
**2026-09-27**. `dsh-github` was created **2026-10-07** as a fork with default branch
`main`, so it is absent from the stale list and the ruleset still targets it:

```
$ gh api repos/opencharly/dsh-github/rules/branches/main --jq 'length'   # dsh-github (created 2026-10-07)
5
$ gh api repos/opencharly/pi-subagents/rules/branches/main --jq 'length'  # a fork created 2026-09-03, BEFORE the apply
0
$ gh api repos/opencharly/crabbox/rules/branches/main --jq 'length'       # a fork created 2026-09-04, BEFORE the apply
0
```

So the ruleset's REQUIRED check applies to `dsh-github`, while the required workflow's
job `if:` skips it (head repo is a fork) — the check is never produced:

```
$ gh pr view 2 --repo opencharly/dsh-github --json mergeStateStatus,mergeable
{"mergeStateStatus":"BLOCKED","mergeable":"MERGEABLE"}
$ gh pr merge 2 --repo opencharly/dsh-github --squash
Required status check "validate / validate" is expected.
$ gh api repos/opencharly/dsh-github/commits/<head>/check-runs --jq '.check_runs[]|select(.name=="validate / validate")|.conclusion'
skipped
```

The predicate fix is the durable root fix; the operator's re-apply is the immediate
unblock.

## Security review (this is a self-modifying-security surface)

The change **narrows** what is skipped and **widens** what is reviewed:

- Before: skip when `head.repo.fork == true` — i.e. skip the org's OWN same-repo PRs
  in any fork repo (over-broad; the deadlock).
- After: skip when `head.repo.full_name != github.repository` — i.e. skip ONLY a PR
  whose head repo is a **different** repository. That is precisely the external-fork
  case the guard was written for: its secrets are unavailable (`secrets: inherit`
  cannot reach them) and its code is untrusted. No same-repo PR is newly skipped, and
  no external-fork PR is newly run.
