# 2026.297.1146 — fix(ci): an EMPTY check set must never arm auto-merge (#248)

## Summary

The `Head check-runs` step of the reusable `charly/pr-validator` workflow — the merge guardrail that arms native auto-merge — could be satisfied by observing **nothing**. Its snapshot's guard is on the **body**: `[[ -n "$body" ]]`. A well-formed API answer that reports ZERO check runs is not an empty body, so it passes that guard; the jq filter yields `{pending:[],bad:[],all:[],total:0}`; every count reads 0; and the step fell through to

```
all 0 check run(s) on this head passed — safe to arm auto-merge
```

with exit 0. The next step, "Enable auto-merge", then ran on a head whose checks the gate had never observed. This is the same fail-open shape #247 removed for the empty body, one level down.

**The fix — the guard now also covers the SET.** A total of 0 is its own class, and it refuses to arm. The exit code is the class, as it is for the four classes #247 introduced:

| exit | class | what it means | remedy |
|---|---|---|---|
| 0 | GREEN | every check on the head passed | arm it |
| 1 | NOT-PASSED | a check on the head did not pass — a FINDING about the change | fix it and push |
| 2 | IN-FLIGHT | a check is still RUNNING — not a finding | re-run this job only |
| 3 | UNREAD | the head could not be read | refuse to arm |
| 4 | EMPTY | the head carries NO check run at all | refuse to arm |

**And the empty set is not a legitimate state for this job.** `arm` has `needs: [validate, lint]`, so the `validate` job — the required context — has COMPLETED by the time this step reads the head, and it left a check run on that head. The `lint` job is unconditional today and left one too. Only this job's own run is excluded, so the non-self set is never empty by construction. A total of 0 therefore means the head's check runs are **not visible here** — a wrong head SHA, an API anomaly, or a lookup that does not cover them — and NOT that the head is green. Measured over 48 merged PRs in 6 org repos: the non-self set was never empty (minimum 2), with the required `validate / validate` present 48/48. Unobserved is not unreachable, so the gate refuses.

**The coverage can fire.** `scripts/head-settle_test.sh` already extracts the **shipped** step's `run:` text and runs THAT against fixtures, and it already restores the pre-#229 shape as its negative control. This change adds a second control, isolated to this one guard: the shipped text with **exactly** the class-4 block removed. The shipped text must NOT reach the arming line on an empty set (exit 4); the control MUST (exit 0). If the guard is removed again, the control proves the coverage can fail.

- `scripts/head-settle_test.sh` — the coverage: the empty-set fixture, the class-4 assertions, the isolated pre-#248 control, and the class-table assertion.
