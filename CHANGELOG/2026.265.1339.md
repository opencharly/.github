# 2026.265.1339 — feat(ci): move ALL branch protection to ONE org ruleset (v5 — body frozen to head)

## Summary

Move **the whole PR-validator + main-branch-protection configuration to ONE org-level ruleset** now that the org is on GitHub **Team** (which unlocks org rulesets; org required-workflows are not available on the free plan). This removes the last per-repo validator config.

**One org ruleset replaces the per-repo main-branch rulesets (391) AND the per-repo validator dispatcher stubs (406), across the 409 active non-fork `main`-default repos.** An organization branch ruleset carries BOTH the `workflows` rule (naming a workflow in another repo at a pinned ref) **and** the ordinary branch rules (required status check, no force-push, no deletion, no creation). GitHub then, for every targeted repo, runs `opencharly/.github/.github/workflows/org-wide-pr-validator-required.yml@main` on its PRs (producing the required `validate / validate` check) **and** enforces the branch rules that require exactly that check.

### Design

- **`scripts/lib-org.sh`** — shared helpers (`discover_repos`, `discover_excludes`, `dispatcher_path_for`, `api_status`), sourced by both cutover scripts.
- **`scripts/org-ruleset.sh`** — the SINGLE owner. `apply` (idempotent): **refuse while any dispatcher survives** → create/update the org ruleset → delete the redundant per-repo rulesets → remove any surviving legacy branch protection → enforce per-repo `allow_auto_merge`. `verify` asserts the whole end state.
- **`.github/workflows/org-wide-pr-validator-required.yml`** — the org-level REQUIRED WORKFLOW the ruleset names, calling the existing reusable `pr-validator.yml@main`; forwards the provider selection.
- **`scripts/retire-per-repo-dispatchers.sh`** + **`.github/workflows/retire-per-repo-dispatchers.yml`** — first cutover step: delete every repo's redundant dispatcher stub (needs the bypass-actor App token for a protected-`main` write).
- **`README.md`** — rewritten to match: the single-owner `scripts/org-ruleset.sh` description, the new retirement script, the one-time cutover order, and removal of the obsolete "install the dispatcher per repo" section.

### Correctness properties (each with a failing-without-it test)

- **API failure != absent, with a real call-site guard.** `discover_repos`/`discover_excludes` RETURN a status and callers check it at the call site (`out="$(fn)" || exit 1`) — a guard inside `mapfile ... < <(fn)` is dead (the subshell status is not propagated), so the excludes read is genuinely guarded. `has_dispatcher` and the `apply` legacy-protection probe classify the HTTP status and abort on anything neither 200 nor 404.
- **Empty discovery yields an EMPTY array** (`mapfile <<<"$empty"` would produce `[""]`); the test asserts `.conditions.repository_name.exclude == []` via jq (a plain grep is insufficient — the hardcoded `ref_name` line also contains `"exclude": []`), plus a non-empty-exclude round-trip.
- **Legacy branch protection removed AND verified** (org rulesets are additive; the classic protection has no App bypass).
- **`verify` asserts the ruleset's TARGET SCOPE** (`repository_name.include == ["~ALL"]`, `protected == false`, `exclude ==` the re-derived non-target set, `ref_name == refs/heads/main`) — a silently narrowed/widened scope would otherwise pass.
- **No admin bypass** — only the `charly-auto-merge` App bypass; `verify` asserts no `OrganizationAdmin`.
- **`verify` parity**: strict required checks, EXACTLY ONE required check, no `pull_request` rule.
- **`actions: write` evidenced**: the permissions table + measured regression **#163** (CHANGELOG/2026.251.0844.md).
