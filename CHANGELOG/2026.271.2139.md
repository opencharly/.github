# 2026.271.2139 — feat(ci): strip the retired version: stamp from EVERY charly.yml, root or nested

## Summary

Extend the org-wide config-version strip to **EVERY `charly.yml` in every repo, root or nested** — the v1 tool fetched only `repos/$ORG/$repo/contents/charly.yml` (the ROOT manifest).

**The gap (measured):** 206 nested `charly.yml` files across 140 repos still carried a strippable `version:` stamp — e.g. `candy/plugin-box/charly.yml`, `plugin-vm/candy/plugin-vm/charly.yml`, `charly/tools/generate-packages/charly.yml`, `distro-cachyos` ×15. The cutover must remove the stamp from all of them.

**The fix, two parts:**

1. **Enumerate every manifest.** Walk every `charly.yml` per repo via the git TREES API (`git/trees/main?recursive=1`, shared helper `list_config_paths` in `lib-org.sh`) and run the filter on each. The root file is simply one more path in that list.
2. **Sharpen the filter predicate (a behaviour change this PR makes).** The v1 filter deleted any `^ {0,8}version:` line. The nested enumeration surfaces manifests where that bare-indent rule would delete a **LIVE** field: `charly/charly.yml`'s embedded default build vocabulary carries an indent-8 `version:` under `distro:` (`#Distro.version`, a real `schema/distro.cue` field asserted by charly's own `distro_cascade_test.go`). The predicate is now **STRUCTURAL**: delete ONLY the indent-0 document stamp or a **direct** `candy:`/`box:`/`deploy:` body stamp; every other `version:` (including under `distro:`) is preserved. This matches `charly migrate`'s canonical predicate (plugin-migrate#12: `stripVersionField` + `stripEntityVersionKey`).

**Safety (the predicate change above is the only behaviour change; the rest is preserved):**
- The filter deletes ONLY the document stamp (indent 0) or a **direct** `candy:`/`box:`/`deploy:` body stamp; a `version:` at indent 16+ (a fenced example in a `description: |` block scalar) is **PRESERVED** — the real `layer-charly-hermes` case; it refuses loudly inside a block scalar. `#Distro.version` (live schema field in `charly/charly.yml`'s embedded vocabulary) is NOT a direct entity child and is untouched.
- A **truncated tree listing is FATAL** — never silently read as "this repo has no charly.yml" (which would leave an unseen nested manifest stamped behind a green run).
- Idempotent (a clean file → `skipped`, never written); a repo with no `charly.yml` → `absent`; a non-404 probe/listing error → FATAL; one file's transient failure → counted `failed`, the wave continues, non-zero exit.
