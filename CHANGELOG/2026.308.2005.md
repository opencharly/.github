# 2026.308.2005 — fix(ci): log in to ghcr.io on every image-build run, not only when publishing

## Summary

**The login step carried `if: inputs.push`**, so a build-only `pull_request` run never authenticated to ghcr.io. A variant repo's `base:` is itself an image in this registry, so the build still **pulls** — and with no explicit login the pull falls back to whatever credential the shared runner carries. On `opencharly-ubuntu` that is a stale/foreign `~/.docker/config.json`, and the pull is denied **even though the package is public**.

```
Error response from daemon: error from registry: denied
```

Measured on four variant repos whose build-only arms failed exactly this way while the same image pulled fine by hand: `pod-crabbox-systemd`, `-code`, `-browser`, `-gpu`.

**Fix:** log in unconditionally. An authenticated read of a public package is always permitted, so this is the deterministic form. The step already reads the token from **stdin**, so no new secret surface.
