needs **no empty commit**, and remove the dead `edited` trigger from the required
workflow (dotgithub#119).

### RCA (8-step, R1) — MEASURED

**Unexpected.** A body-only fix after a BLOCK still required an empty "re-freeze"
commit even after #119 added `edited` to the required workflow's `on.types`.

**Mechanism (four live experiments):**

| # | Experiment | Result |
|---|---|---|
| 1 | Plain per-repo workflow `on: pull_request: [edited]` | **FIRES** on a body edit |
| 2 | Plain per-repo workflow `on: pull_request: [labeled]` | **FIRES** on a label add |
| 3 | The org **required** workflow lists `edited`; edit the PR body | **NO RUN** (×3) |
| 4 | The org **required** workflow already lists `ready_for_review`; draft→ready | **NO RUN** |

Experiments 3–4 prove a **required workflow ignores `on.types` entirely** — it
acts only on the default push-driven types. So #119's `edited` never fired, and
no listener can live in the required workflow. A **plain per-repo** workflow fires
on both. The listener therefore ships as a plain per-repo file + a distributor.

### Fix

Adding a `rerun` label re-runs the PR head's FAILED `charly/pr-validator` run. A
re-run reuses the SAME `GITHUB_SHA` and updates THAT run's `validate / validate`
check run IN PLACE — **no duplicate same-name check run** — clearing POISON and
re-reading the corrected body. Capability-free (`actions: write` only — no
`checks: write`); loop-safe (it only POSTs a re-run).
