# 2026.279.0837 — fix(validator)!: restore the count-based auto-close and exclude clear infra INCONCLUSIVEs from the max (#170)

Closes #170.

## Summary of changes

The org-wide `charly/pr-validator` auto-close step bounded the PR loop with a **per-class**
number after `opencharly/.github#169`: **ONE** `INCONCLUSIVE` closed a PR immediately, via a
non-configurable `INCONCLUSIVE_THRESHOLD=1`. An `INCONCLUSIVE` is the review engine producing
**no answer** — not a code finding — and the recent INCONCLUSIVEs are clear **infrastructure**
failures, so this closed PRs for reasons that were not their diff.

**Measured evidence (the RCA).** 143 `## validator INCONCLUSIVE` verdicts across the org
(Sept = 128, Oct = 15), by the class the emitted notice carries:

| signature | count | meaning |
|---|---|---|
| `provider-unanswered` | 70 | the ollama-cloud endpoint never answered |
| `verdict-less review output` (default) | 38 | the review step aborted before producing a verdict |
| `engine-defective` | 30 | turn 1 completed, a later turn failed (context growth) |
| `attempt-cap` | 4 | the generation ran past `AI_REVIEW_ATTEMPT_TIMEOUT` |
| `empty-completion` | 1 | `max_tokens` spent on reasoning before any answer |

The smoking gun is `opencharly/charly#802` (auto-closed 2026-10-06T02:22:53Z):

```
## Auto-closed: 5 non-PASS verdicts on this thread
**Closed after** ONE `INCONCLUSIVE` verdict (INCONCLUSIVE_THRESHOLD=1).
Verdicts on this thread: **4** BLOCK and **1** INCONCLUSIVE
(AI_REVIEW_AUTO_CLOSE_AFTER=20 bounds the BLOCK class)
```

Four real findings and a **20-round** allowance, closed by **one** infra `empty-completion`.

### Fix — restore ONE count-based bound, exclude clear infra

- **One count again.** `AI_REVIEW_AUTO_CLOSE_AFTER` (org default 5; charly overrides to 20)
  bounds `BLOCK` + engine/EVAL `INCONCLUSIVE` together. The `INCONCLUSIVE_THRESHOLD=1`
  one-shot is removed.
- **Infra is excluded.** A clear INFRASTRUCTURE INCONCLUSIVE does **not** increment the
  count, so it can never close a PR on its own. The split is computed in `Run the review
  engine` (`inconclusive_infra`), carried through `Parse verdict`, and read by the auto-close
  step as `THIS_INFRA`.
  - **INFRA (not counted):** provider stall / HTTP rejection, whole-request attempt cap,
    generation-budget empty completion, a discarded non-BLOCK verdict, a killed step
    (rc 124/137 — the runner/abort class).
  - **EVAL (counted):** engine-defective, an unrecognised engine-terminal marker, and any
    other verdict-less run. `engine-defective` **wins** over a co-present provider rejection
    (the engine ran and failed a later turn — the enlarged-context class).
- **The emitted notice is the tie.** The INCONCLUSIVE notice carries the exact literal
  `Verdict class: infra` for an infra run; the counter matches that literal and excludes it.
  Both classes still keep the required check **RED** (unreviewed code must never merge).
