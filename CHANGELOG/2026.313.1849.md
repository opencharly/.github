# 2026.313.1849 — fix(ci): discovery pages REST and refuses a truncated repo set (#290)

Org-wide discovery no longer dies on a flaky multi-page listing: it pages REST at one named size and **refuses a truncated repo set**, so a partial read can never read as a smaller org. Measured live: the reconcile that failed four consecutive attempts at `FATAL: discover_repos failed` now examines the whole org and exits 0.

## Summary

`discover_repos` issued one `gh repo list --limit 1000` GraphQL listing. At this org's size that is five requests, and its later pages returned 502/504 intermittently — so every org-wide script (`org-ruleset.sh verify`, `reconcile-tag-on-merge-callers.sh`, both retirement scripts, `governance-reconcile.sh`) aborted at step zero, before reading a single repo.

Measured **interleaved**, so the variable was the request and not the minute:

```console
$ gh repo list opencharly --limit 1000 --json name,isArchived,isFork,defaultBranchRef --jq 'length'
486
$ gh repo list opencharly --limit 200 --json name,isArchived,isFork,defaultBranchRef --jq 'length'
200
$ gh repo list opencharly --limit 1000 --json name,isArchived,isFork,defaultBranchRef --jq 'length'
HTTP 502: 502 Bad Gateway (https://api.github.com/graphql)
$ gh repo list opencharly --limit 200 --json name,isArchived,isFork,defaultBranchRef --jq 'length'
200
```

The fix removes the failure instead of absorbing it:

- **`discover_all`** pages REST at ONE named page size (`DISCOVERY_PAGE_SIZE`) and emits `<name>\t<archived>\t<fork>\t<default_branch>`.
- **`discover_repos`**, **`discover_excludes`** and a new **`discover_membership`** filter that read — each as its OWN paged, count-checked fetch, so no single read can understate the org. They are independent reads (a bash command substitution cannot memoise across calls), which means the second can fail after the first succeeded, and a repo created between two of them is in neither set. `org-ruleset.sh` aborts on a failed exclude read and that path is covered below; collapsing the reads to one per script is `#292`, filed rather than folded into this gate.
- **`org-ruleset.sh`** no longer issues its own `--limit 1000` listing for the membership arm; that call was the same failing shape and could fail alone while the rest of `verify` succeeded.

**Two controls, and they are different controls.** `--paginate` returns non-zero if ANY page fails, so a 502 can never be mistaken for the end of the org. Then the discovered **count** is checked against the org's own total (`public_repos + total_private_repos`), because a merely *truncated* successful response would still read as a smaller org to every caller — the same class as the `mapfile < <(fn)` trap the file already documents, where emptiness is not a failure signal on its own.

No retry anywhere: a retry would absorb the failure rather than remove it (R3).

**Round 1 restored a guard I wrongly deleted.** The first version of this body claimed the three filters "filter that single read", so the exclude read "cannot fail independently" — and on that false premise the diff removed the case that exercised the excludes abort.
