**ONE org-level source for the candy-manifest gate, and retirement of the ~376 stale per-repo copies.**

~376 opencharly repos carried a hand-rolled `.github/workflows/deploy.yml`
(`name: candy`, job `build`) that CI-time-cloned `opencharly/charly` at a
**hand-pinned tag** and ran `charly box validate`. 298 of the 376 were frozen at
`v2026.238.1242`; the candy stubs carry **16 distinct** charly pins — **374** name an
inline `v2026.*` tag (15 distinct tags) and **plugin-herdr / pod-herdr** pin charly via
a git-submodule gitlink at `v2026.251.0841` (the 16th) — and nothing advanced them (all
measured with pasted commands below). The schema-versioning-removal cutover made this
acute: the cutover deleted the authored top-level `version:` field, and the old pinned
charly's `box validate` **requires** that stamp, so every version-strip PR fails its OWN
repo CI with `schema 2026.232.0520 is required (found ""). Run: charly migrate`.

This replaces that class with ONE org-level source, mirroring the established
`retire-per-repo-dispatchers` pattern (one source, zero per-repo copies):

- **`.github/workflows/candy-validate.yml`** — a new `on: workflow_call` reusable.
  It clones `opencharly/charly` at the org variable **`vars.CHARLY_VERSION`** (the
  single knob), builds the binary, and runs `charly box validate`. It **skips
  cleanly (green)** when a repo has no `charly.yml`, and **fails loud** when the pin
  is unset/invisible (no bundled fallback, same fail-closed contract as the org
  validator). Called from a job named `candy`, its inner job named `validate`
  produces the **`candy / validate`** check context (verified live below: a reusable's
  nested job renders as `<caller-job> / <inner-job>`; the retired per-repo stub
  produced bare `build`).
- **`scripts/retire-per-repo-candy-gates.sh`** + the workflow
  **`.github/workflows/retire-per-repo-candy-gates.yml`** — the one-shot org cutover
  that DELETES the stale stubs. It runs as a workflow because a delete on a protected
  `main` needs a ruleset-bypass commit author — the `charly-auto-merge` App (the
  workflow mints that token), same precedent as `retire-per-repo-dispatchers`.
  **SAFETY:** a `deploy.yml` is deleted **only** when its parsed top-level `name:` is
  exactly `candy` **and** its body carries the `charly box validate` signature;
  `name: marketplace`, `name: docs`, and every other real gate are **skipped, never
  touched**. Idempotent (absent files skipped); a non-404 probe / metadata failure
  **aborts** (never reads as "absent"); a 403 aborts with the `workflows: write`
  remediation.
- **`scripts/retire-per-repo-candy-gates_test.sh`** — offline mock-`gh` test,
  wired into `.github/workflows/validator-harness.yml`. It asserts the happy path, the
  real-gate safety rule (`name: marketplace` never deleted), the renamed-stub safety
  rule (a `candy`-named file with no validate signature never deleted), idempotency,
  the API-abort, the metadata-abort, the delete-failure counters, and the 403 abort.
- **`.github/tests/validator-gate-harness.py`** — extended to drive the reusable's
  **real `run:` bodies** offline (the same technique as the pr-validator scenarios):
  the skip path (no `charly.yml` → `present=false` → the pin-required step's `if`
  resolves false → green) and the fail-loud path (`charly.yml` present + pin unset →
  non-zero `::error::`).
- **`scripts/governance-claims.tsv`** — two rows pinning the reusable's single-knob
  invariant (require `vars.CHARLY_VERSION`, forbid a hand tag `--branch v20`).
- **`README.md`** — documents the reusable, the cutover, and the deferred activation.

**Activation is deliberately deferred (and this is the load-bearing design point).**
The reusable is NOT named by the org ruleset as a required workflow. The current
`vars.CHARLY_VERSION = v2026.271.0950` names a release whose `box validate` **still
requires the retired stamp** (re-measured live below: `schema 2026.261.1747 is required
(found ""). Run: charly migrate`). Making it **required** at that pin would re-break
the very PRs this replacement exists to unblock. The stale-pin deadlock is removed
either way (the old pins are deleted); the reusable becomes nameable org-wide once the
pin names a release carrying the schema-versioning removal (the `charly#716` host
leg). The org ruleset `23827016` currently requires only `validate / validate`; the
candy check was and remains **not** required, so this PR adds no new required gate and
makes no `org-ruleset.sh` change.

**Closes / relates to:** relates to `opencharly/charly#716` (the schema-versioning
removal host leg) and `opencharly/charly#717` (the transitive-pin reconcile wave);
this is the org-CI leg that unblocks the per-repo version-strip PRs
(plugin-box#19 / plugin-deploy-local#11 / plugin-deploy-vm#31).

**Breaking change + rollback:** `none` — purely additive (a new reusable, a new
one-shot cutover script+workflow, a new test + harness coverage, two governance rows,
README). The cutover deletes per-repo files only when the App-token workflow is
dispatched, and only the verified `name: candy` + `charly box validate` stub.
Rollback: revert this PR; the per-repo stubs are recoverable from each repo's git
history.
