# 2026.271.0809 — feat(ci)!: retire the rerun-label channel; body-fix rerun is manual gh run rerun

## Summary

**Retires the automatic `rerun`-label channel entirely.** Re-running the gate after a PR
**body edit** is now a **manual `gh run rerun <run-id>`**.

### Why (R1 — RCA)

Operators observed validator runs appearing after comments and asked why. Verified against the
live workflows and the GitHub docs:

- **Nothing triggers on comments.** The org-required workflow is
  `pull_request: [opened, synchronize, reopened, ready_for_review]`; `issue_comment` appears in
  no workflow, and GitHub docs confirm `issue_comment` is a **separate** event — `pull_request`
  never fires on comments.
- **The automatic rerun was the `rerun` label + the scheduled `rerun.yml` sweep.** Timeline
  evidence: the `rerun` label was applied at 07:40:55/07:40:57/07:41:00 and the sweep re-ran the
  failed runs at 07:44. A label can be added for **any** reason — including a comment — and the
  sweep re-ran the gate **without a body change**.
- **A body-edit auto-trigger is impossible for the required workflow.** GitHub docs
  ("Troubleshooting rules"): *"Any filters you specify for the supported events are ignored —
  for example, branches, branches-ignore, paths, types and so on. The workflow is only
  triggered, and is always triggered, by the default activity types"* (`pull_request`:
  `opened, synchronize, reopened`). The earlier `edited` attempt (#119) was removed for exactly
  this reason (#121).

Fix: **remove the automatic channel; make the body-fix rerun explicit and manual.**

### The manual body-fix path (documented)

```
gh run list --repo <owner>/<repo> --json databaseId,headSha,conclusion   # find the failed run
gh run rerun <run-id>                                                    # re-run it in place
```

A re-run reuses the SAME `GITHUB_SHA` and updates THAT run's `validate / validate` check run
IN PLACE — no duplicate same-name check run, so it clears POISON without an empty re-freeze
commit. (GitHub docs: "Re-running workflows and jobs".)

The `rerun` **label** may still exist in repos (created by the retired `ensure-rerun-label`);
it is now **inert**. Deleting the label definitions org-wide is a safe follow-up, left out here
to keep the diff reviewable.
