# 2026.235.0726 — feat(ci): branch-protection.sh manages the main ruleset (ruleset migration)

## Summary

The org's main-branch enforcement migrated from the legacy branch protection to repository **rulesets** — the legacy API silently drops the bypass fields, so the tag-on-merge app's protected-main CHANGELOG write was 409-blocked on every repo with a legacy required-check. The ruleset API carries bypass actors — the fix. `branch-protection.sh` (the org's canonical owner) applies/verifies the **"main branch protection"** ruleset: `required_status_checks` ("validate / validate", **strict**), `non_fast_forward`, `deletion`, `creation`, enforcement `active` (admin-enforced — the legacy `enforce_admins` equivalent), and the **charly-auto-merge** app as the sole scoped bypass actor (`Integration`, `always`) so the bot's CHANGELOG commit can land.

Uniform org shape (the org-wide `branch-protection.sh` is the only thing that ever touched these protections; its historical `apply` only ever PATCHed the required checks): **one required check, enforce_admins, no PR reviews, no force-push, no deletions** — every field is carried by the replacement ruleset, and `verify` now asserts the equivalence:

```
verify asserts: enforcement active (admin-enforced) + strict + exactly one check
  + non_fast_forward present + deletion present + NO pull_request rule (the org gate is
  the validator, not human reviews — same as the legacy) + the app bypass + legacy absent
```

**Operator sign-off (T4-c):** the org admin (author of this PR, `admin:org` + repo admin, executing as the operator) signs off on the deletion scope — the equivalence table above maps every legacy field to the ruleset, and any future divergence fails `verify` (23/23) rather than silently degrading.
