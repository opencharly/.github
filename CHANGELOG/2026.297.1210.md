# 2026.297.1210 — test(gate): give the owner-dir guard an assertion that can fail (#253)

## Summary

The stale-pointer control that landed in #252 (opencharly/.github#246) has **two owner guards** in `owner_present`: the owner path must be a **DIRECTORY**, and it must not be **EMPTY**. The self-test asserted the *empty-dir* case **twice** — out5 created an empty owner dir while claiming to test an absent one — so the **directory guard had no coverage that could fail**. The validator's PASS on #252 found it, and this change closes it.

Files: **`scripts/governance-reconcile.sh`** — one file, and the diff is **test + comments only**: the checker's executable lines are **byte-identical** to `origin/main` (block 3). Nothing about the gate's behaviour changes; what changes is that the gate's own suite can now **tell** whether a guard is load-bearing.

Three concrete edits:

- **out5 becomes the truly-absent case.** Its fixture ran `mkdir -p "$tmp/unmaterialized/absent-repo"`, so the owner dir was *present and empty* — out6's case again. The empty dir is gone; the comment now says exactly what is tested (*the owner directory does not exist at all*).
- **out6 keeps the empty-dir case**, with the distinction from out5 written down: here the owner dir **exists and is empty** (an uninitialized submodule path in a light checkout); there it **does not exist**.
- **A new out9 asserts that a NON-DIRECTORY owner path skips.** This is the assertion that **discriminates**. The fix is deliberately *not* an assertion for the absent case: an absent owner and an empty owner are the **same verdict**, and `ls -A` on a missing directory yields nothing — so an absent-owner assertion **cannot fail** if the `-d` guard is removed, and a test that cannot fail is invalid. The guard is load-bearing only when the owner path is a regular **file**, where `ls -A` prints the file's name, the owner looks materialized, and the control turns into a **false red**.

The prose is corrected too: the self-test's blocks are **two kinds of assertion**, and the header comment now names them — **FAIL** (out4 a stale pointer, out7 an absent top-level surface) and **SKIP** (out3 a same-named root file, out5 an absent owner, out6 an empty owner, out8 a name-collision directory, out9 a non-directory owner). The #252 body's "two false-red guards" wording mixed the FAIL assertions in with the two skip guards; the script's own header now states the three filesystem states that are not a materialized owner.
