# 2026.327.1113 — fix(labels): validate the closed set without a pipefail/SIGPIPE race

## Summary

`scripts/labels.sh` validated a taxonomy value with `printf '%s\n' … | grep -qxF "$value"` under `set -o pipefail`. `grep -q` exits on its first match, `printf` then takes SIGPIPE, and pipefail reports the WHOLE pipeline as failed — so a **valid** `category:`/`type:` value is rejected as "not a taxonomy value". It is a race: whether the pipeline fails depends on whether the writer finishes before the reader exits.

Measured against the real org backfill (783 open issues):

| step | outcome |
|---|---|
| `classify` | 783 rows, 248 with both axes decided |
| `apply --dry-run` | PLAN 247, failed 1 |
| `apply` | applied 236, skipped 535, **failed 12** |
| re-apply the 12 rejected rows after this fix | `applied=12 skipped=0 failed=0` |

236 + 12 = the full 248, so no row was actually invalid. The defect was in the validator, and it would have silently rejected rows on every future `apply`/`sync`/`audit` run.

Root fix: every `printf … | grep -q` pipeline in `labels.sh` becomes a here-string (`grep -qxF "$value" <<<"$(…)"`), or an `awk` first-column test where the input is a two-column table (`cmd_retire`). A structural test arm fails the suite if such a pipeline is reintroduced.

Files:

- `scripts/labels.sh` — `valid_axis_value` + the audit's forbidden/retired/spec checks + `cmd_retire`'s presence test + `verify_close_one`'s category check.
- `scripts/labels-test.sh` — arm 7b: asserts `valid_axis_value` uses a here-string and that no `printf … | grep -q` pipeline remains.
