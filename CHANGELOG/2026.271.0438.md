# 2026.271.0438 — fix(ci): make the governance claims wrap-safe (no false red on a reconciled tree)

## Summary

**Follow-up to `opencharly/.github#128`** (the merged cross-surface reconciliation gate). This fixes **two defects in that gate** that make it RED on a CORRECT, reconciled tree — a false red, exactly the class the gate exists to prevent (a governance gate that cries wolf gets ignored).

**Defect 1 — the matcher is line-based, so a wrapped phrase is missed.** The prose in these surfaces wraps at a fixed column, so a multi-word canonical phrase straddles a line break and a plain line-based `grep` reports it ABSENT. **Fix:** match against a **whitespace-normalized** copy of the file (`tr '\n' ' ' | tr -s '[:space:]' ' '`), so a phrase spans a wrap. This **keeps the full, specific phrases** in the manifest — no loosening of the guardrail.

**Defect 2 — one `forbid` pattern fired on the gate's own quoted negation.** The `signoff_account_gate … forbid VALID — operator-DELEGATED` rows flagged the account-gate's own explanatory sentence ("… a self-asserted `VALID — operator-DELEGATED` … is **forgeable and is NOT a sign-off**") — a legitimate MENTION of the retired form, not the retired form. **Fix:** forbid the retired form's actual wording (`labelled delegated and carrying`), so the negation no longer trips it. Two `require` rows also move to the shared wrap-safe anchor (`Agent:. FIRST`, `takeover, ever`) whose full clause differs by surface; this is required by defect 1's shared-phrase reality, not a weakening — the phrase is unambiguous and the same claim is checked on every surface.
