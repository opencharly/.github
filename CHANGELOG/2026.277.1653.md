# 2026.277.1653 — fix(validator): classify INCONCLUSIVE from the engine's own terminal line (#133)

## Summary

The org-wide validator's `## validator INCONCLUSIVE` notice reported a class the review
engine never named, and explained it with a narrative that contradicts this repository's
own committed contract. `opencharly/.github#133` reported the template mislabel; the RCA
below found the mechanism is worse than a stale string — the classifier **could not**
separate the classes at all.

Three changes, one commit:

1. **The class is now read from the engine's own terminal line** over the complete marker
   set `review.go` can emit — `exceeded AI_REVIEW_ATTEMPT_TIMEOUT` → `attempt-cap`,
   `produced no answer` → `empty-completion`, `provider never answered or stopped
   streaming` → `provider-unanswered`, any other engine marker → `engine-terminal-other`
   (which **defers to the engine's quoted line** rather than inventing a cause). The notice
   quotes the run's own `inconclusive:` line and its own `request —` line in a
   `**Measured in this run**` block.
2. **The folding defect is removed at its root (R1).** The pre-fix classifier keyed one
   flag on `grep -qiE 'inconclusive:|provider unanswered|Client[.]Timeout exceeded|context
   deadline exceeded'`. Every terminal line the engine emits begins with `inconclusive:`,
   so that match was TRUE for **every** class — one flag, one canned narrative, for all of
   them. The fallback now fires only when the engine named **no** class at all.
3. **R5 — three dead knobs deleted, not forwarded:** `AI_REVIEW_MAX_ATTEMPTS`,
   `AI_REVIEW_MAX_TURNS`, `AI_REVIEW_TOOL_RESULT_MAX_BYTES` have **zero** readers in every
   `.go` file of `opencharly/plugin-review` (their readers went with the tool loop and the
   per-turn retry loop). Removed from the review step's `env` and from the review contract
   (`charly.yml`).
