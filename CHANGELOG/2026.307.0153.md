# 2026.307.0153 — feat(ci): the reusable image-build workflow and its executed tests (W5.4, successor to #274)

## Summary

The org has no image-build path (`ls .github/workflows | grep -i image` → nothing), so W5's twelve `pod-crabbox*` repos each face hand-rolling a build. This adds ONE reusable workflow, its test, and one step in `workflow-checks.yml` to run that test.

**Diff — three files.**
- `.github/workflows/image-build.yml` (new, 13 steps)
- `scripts/image-build-tag_test.sh` (new)
- `.github/workflows/workflow-checks.yml` (one step added)

**Invariant:** image tag == git tag, without the `v`, so `import: '@github.com/opencharly/pod-crabbox:v2026.x'` and `ghcr.io/opencharly/pod-crabbox:2026.x` name one build.

**What the workflow does, step by step:** refuse an unpinned `vars.CHARLY_VERSION`; clone and build charly at that pin; **ensure the builder** (`uidmap`, `slirp4netns`, `skopeo`, pinned `buildkit v0.34.1`, and `/run/buildkit` chowned to the invoking user); **preflight** (presence of all five tools, `unshare -Ur`, `/etc/subuid`, `/etc/subgid` — failing by name); derive the tag; log in to ghcr with the token on stdin; build; print the builder's log unconditionally; verify the pushed digest; summary.

## How tested

**The tag derivation and the publish arm are executed by a test, on every host.** `scripts/image-build-tag_test.sh` extracts the shipped `run:` text of two steps and drives them; both step bodies take every input from environment variables, so neither carries a GitHub expression and both are runnable outside Actions. It is wired into `workflow-checks.yml`.

```console
$ bash scripts/image-build-tag_test.sh
image-build-tag_test: OK (explicit tag verbatim; v-tag push strips the v; build-only derives ci-<sha> and announces it; a publishing run without a tag refuses by name; the build-only arm is load-bearing)
rc=0
```

Case 5 drives the build step with a stub binary: `PUSH_INPUT=false` must NOT pass `--push`; `PUSH_INPUT=true` must; both must carry `--tag`. **Mutation-proven** — with the `--push` arm removed from a copy of the workflow the test fails:

```console
$ bash scripts/image-build-tag_test.sh
FAIL: a publishing run MUST pass --push; got: box build pod-crabbox --tag ci-abc123
rc=1
```

The tag-derivation control likewise strips its `ci-<sha>` arm and requires case 3 to go RED.
