# 2026.287.2230 — feat(ci): reconcile the per-repo tag-on-merge callers (the missing update half) + the verify arm

## Summary

**The update half `retire-per-repo-dispatchers.sh` never had, plus the verify arm `#192` records as missing.** Every repo's `.github/workflows/tag-on-merge.yml` is a **copy** of this repo's canonical template, installed at bootstrap — and `install_tag_caller()` (`bootstrap-repo-main.sh:125`) **returns early when the file exists** (*"already present — untouched"*), so the bootstrap installs into **new** repos and **structurally cannot update an existing one**. `#189` pinned the template to an immutable Node 24 commit; the distributed copies were never swept, and nothing bound a copy to the template. This script is that binding.

**TWO ORTHOGONAL QUESTIONS, reported as two columns — because merged, one number read `0` on the question that matters.** Measured against the live org (436 repos examined, 32 excluded):

```
  COLUMN 1 — pin (the T3 / Node-20 question)
    pin-mutable (still unpinned)  : 423      <-- the URGENCY column
    pin-pinned  (immutable)       : 6
    pin-no-uses                   : 0
    caller-absent                 : 7
  COLUMN 2 — prose (the template-revision question)
    prose-canonical               : 1
    prose-drifted                 : 428      <-- the TIDINESS column
  BOTH (mutable pin AND drifted prose) : 423
  NEITHER                              : 1
  could-not-see (excluded by discover_repos) : 32
```

**`BOTH = 423` is the finding, not a coincidence:** the two coincide because every copy froze at whatever template revision existed at its bootstrap. One reconcile against the canonical template fixes both — and the counts are still reported separately, because *"is the uses-line the only difference?"* was the wrong predicate: it put **all 428** in one bucket and answered `0` to the Node-20 question.

**Modes.** `verify` is the **default and read-only** (idempotent — this *is* the verify arm the issue says is missing, and it keeps holding the line after any rollout). `--apply` brings **differing** callers to canonical. **`absent` is REPORTED, never installed**: a repo with no caller has never had one, and installing a dispatcher there would change that repo's behaviour (it would start minting CalVer tags and CHANGELOGs it never had) — that is `#204`'s decision, not this PR's.

**`--apply` is NOT run here.** The ~423 default-branch writes are the operator-authorized class `#192` names; they are filed as **`#204`** with these measured counts and a canary-first plan. `could-not-see` is **named** (from the existing `discover_excludes()`), never implied.

**The comparison anchor is the template's content at a named commit** — blob `2f0809a94dcdd99f3d63c087b996836634667a75` at this base, canonical pin `actions/github-script@3a2844b7e9c422d3c10d287c895573f7108da1b3` (v9.0.0, node24) — never a remembered string.

**Two gates exist for this class and neither covers distributed copies**, which is why this script exists: `scripts/check-action-runtimes.py` audits **this repo's** workflows only, and `scripts/governance-reconcile.sh` reconciles **prose claims**, not file copies. `retire-per-repo-dispatchers.sh` covers the **deletion** half of the same family.
