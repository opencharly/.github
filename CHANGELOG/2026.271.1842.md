# 2026.271.1842 — feat(org-ci): ONE-shot minimal-diff config version: strip cutover

## Summary

**ONE-shot, minimal-diff org cutover that deletes the schema-versioning-removal cutover's retired authored config `version:` stamp from every repo's `charly.yml` — mirroring the `retire-per-repo-candy-gates` precedent exactly (App-token, ruleset-bypass commit to protected `main`, per-repo resilience, offline mock-`gh` test).**

The schema-versioning-removal cutover deletes the authored config `version:` field, and the
org still carries it widely on `main`. **Measured over the org TARGET set** — the 423
active, non-fork, `main`-default repos that `scripts/lib-org.sh`'s `discover_repos`
enumerates, on **2026-09-28**:

| metric | count |
|---|---|
| target repos scanned | 423 |
| carry a `charly.yml` | 402 |
| no `charly.yml` (→ `absent`) | 21 |

(396 = 394 stripped + 2 preserve-only. The corpus is being stripped CONCURRENTLY, so these
are a point-in-time snapshot; the docstrings, script header, workflow header and README all
state these same numbers and the same arithmetic.)

The host leg of the removal (`opencharly/charly#716`) is **NOT landed**, so NO released
charly accepts or needs the strip — and `charly migrate` **REFORMATS the whole file** (~100
cosmetic lines of churn per file, incl. trailing-whitespace changes INSIDE `description:`
block scalars). Across ~400 repos that is an unreviewable diff for a one-field removal. This
PR strips with a **MINIMAL-DIFF, parser-safe** line filter instead.

- **`scripts/strip-config-version.sh`** — the org-wave driver. Enumerates repos via the
  shared `discover_repos`, fetches each `charly.yml` through the Contents API (with the
  **git-blob fallback** for > 1 MB bodies), runs the filter, and PUTs the stripped content
  back with the App token and the message
  `chore(schema): drop the retired config version: stamp (org-wide cutover)`. Counters:
  `stripped= absent= skipped= failed=`. Idempotent; `DRY_RUN=1` reports what WOULD change
  without committing; a **403 aborts loudly with the `contents: write` remediation**; a
  per-repo transient failure is counted `failed` and the **wave CONTINUES** (the #142 lesson).
- **`scripts/_strip-filter.py`** — the filter. A line is deleted **ONLY** when it matches
  `^ {0,8}version:` — the document stamp (indent 0) or an entity-body stamp (indent 8, and
  indent 4 in the two 2-space manifests `action-review`/`eval-charly`). A `version:` line
  **indented 16 or more is a fenced YAML example inside a `description: |` block scalar and
  is PRESERVED** (e.g. `layer-charly-hermes` line 39
  `                version: 2026.156.1921   # mandatory CalVer` MUST survive). It also tracks
  block-scalar context and **refuses LOUDLY** (exit 3, nothing written) if a matched line
  ever sits inside such a scalar. Every other byte is byte-identical.
- **`.github/workflows/strip-config-version.yml`** — the one-shot `workflow_dispatch`
  (optional `dry_run` + `repos` inputs) that mints the `charly-auto-merge` App token and runs
  the script. **Shell-injection-safe**: `repos` is passed via `env: REPOS` and expanded as a
  quoted array (`read -ra repo_args <<<"$REPOS"`), never interpolated into `run:`.
  `contents: write` (charly.yml is not a workflow file, so no `workflows: write`).
- **`scripts/strip-config-version_test.sh`** — offline mock-`gh` test covering all four
  required cases + resilience, wired into `.github/workflows/validator-harness.yml`.
- **`scripts/fixtures/layer-charly-hermes-charly.yml`** — the REAL `layer-charly-hermes`
  `charly.yml` (git blob `988bdc946e548f79baeec61b6e88a4a8d9f9c534`, sha256
  `c5fc9280…b9e04`) committed as a fixture to **lock the code-block-preservation case**.
- **`scripts/lib-org.sh`** — **R1 fix**: `api_status()` used
  `awk 'NR==1 { print $2; exit }'`, which under `set -o pipefail` sends `printf` SIGPIPE
  (exit 141) whenever the response body exceeds the 64 KiB pipe buffer — every `charly.yml`
  over ~64 KB (measured 100 KB on `distro-arch`) killed the probe. Dropped the `exit`; awk
  consumes the whole input (it still prints only line 1). Shared helper — proven
  non-regressive against all four existing owner-script tests below.
- **`README.md`** — documents the cutover; registers the new test in the harness list.
