## feat: rename-then-dispatch validation flow

### The change

The validator now:
1. **Renames the CHANGELOG placeholder first**, pushes, then dispatches
   a validation run on the PR branch via `workflow_dispatch` (which
   always runs — no approval), and exits.
2. The **dispatched run** validates ONCE (AI review) and enables native
   auto-merge. Its check lands on the PR head (verified: dispatch on
   the PR branch creates the check on the PR head).

Fix pushes trigger `pull_request: synchronize` normally (author pushes,
no approval) and re-validate. The GITHUB_TOKEN rename push creates one
inert `action_required` run that never runs and never blocks.

### Why

GITHUB_TOKEN pushes create `action_required` runs for `synchronize`.
By dispatching validation explicitly (not relying on synchronize), the
loop is broken: validation is triggered by the rename, and the check
lands on the PR head.

### How tested

Verified: a `workflow_dispatch` on the PR branch creates a check-run on
the PR head SHA. This PR's landing will confirm the full flow.
