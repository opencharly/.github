# 2026.272.0802 — docs: tailored AGENTS.md signpost (dotgithub) (#286)

## Summary

Final leg of umbrella campaign `opencharly/opencharly#286`: add a tailored, thin,
harness-neutral `AGENTS.md` signpost to `opencharly/.github` (the `dotgithub`
repo), the `opencharly` org's GitHub-level configuration source — **and fix the
regression the signpost surfaced in this repo's own governance gate.**

**1. `AGENTS.md` signpost (docs).** The README was already a good user overview
and is kept as-is. `AGENTS.md` documents what the repo is (the org-wide required
PR-validator workflow, the reusable `pr-validator.yml`, the org branch ruleset
`scripts/org-ruleset.sh`, the CalVer tag-on-merge mechanism, the
`candy-validate.yml` org gate, the inherited PR template), the R0 owning skills
(`/charly-internals:repo-setup`, `/charly-internals:git-workflow`), the real
validation commands, the self-modifying-security caution, and a landing pointer.

**2. The gate fix (CI script) — root-caused, not parked.** Adding a root
`AGENTS.md` to this repo turned this repo's own
`scripts/governance-reconcile.sh` check RED:

```
$ bash scripts/governance-reconcile.sh        # default root = this .github checkout
FAIL  footer_order/umbrella AGENTS.md — required phrase ABSENT from AGENTS.md (/Agent:. FIRST/)
FAIL  takeover_window/umbrella AGENTS.md — required phrase ABSENT from AGENTS.md (/window is 60 minutes/)
FAIL  comment_first_takeover/umbrella AGENTS.md — required phrase ABSENT from AGENTS.md (/takeover, ever/)
FAIL  successor_protocol/umbrella AGENTS.md — required phrase ABSENT from AGENTS.md (/RESOLVED — superseded by #<n>/)
FAIL  signoff_account_gate/umbrella AGENTS.md — required phrase ABSENT from AGENTS.md (/posting ACCOUNT is the entire gate/)
FAIL  auto_close_threshold/umbrella AGENTS.md — required phrase ABSENT from AGENTS.md (/AI_REVIEW_AUTO_CLOSE_AFTER., default 5/)
governance-reconcile: checked=13 skipped=21 fail=1
```

**RCA (R1).** The gate's OWN header comment (lines 54–58) states a bare
(non-`dotgithub/`-prefixed) path names a SIBLING-repo surface relative to the
UMBRELLA root — `AGENTS.md` is "the umbrella `AGENTS.md`" — and that such a
surface is "absent in a standalone .github checkout, so it SKIPS cleanly". But
`resolve_path()` unconditionally tried `[[ -f "$rt/$p" ]]` FIRST, so in a
standalone `.github` checkout it resolved the bare `AGENTS.md` to whatever file
sat at the repo root. Until this PR there was no root `AGENTS.md`, so the latent
bug never fired; adding the signpost made the gate assert the *umbrella* rulebook
rows against a repo signpost that carries no rule body. The mechanism: the
resolver cannot distinguish the umbrella root from a standalone `.github` root.

**The fix** makes `resolve_path()` honor the documented contract: a bare path
resolves only when the root MOUNTS the `.github` repo as `dotgithub/` (the
umbrella discriminator); otherwise it returns empty, so the sibling rows SKIP
visibly exactly as the header documents. A regression self-test locks both
directions (bare path SKIPS in a standalone root even when a same-named file
exists; bare path RESOLVES in an umbrella root). This strengthens the gate — it
removes a false-red class — and changes no assertion about the surfaces
themselves.

The one surviving `CLAUDE.md` token is `charly.yml`'s `AI_REVIEW_PROMPT`
validator rulebook — the gate's own instruction surface, a T4
self-modifying-security surface deliberately NOT edited by this docs campaign PR
(tracked as `opencharly/.github#140`); it is reported here, not implied clean.
