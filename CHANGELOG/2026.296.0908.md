|---|---|

A review that errored is `needs-attention`, never `reviewed` — labelling a failed run "reviewed" would be

## How tested

**The decision, from a real verdict** (`crabbox#16`, completed, confidence high):

```console
$ jq -r '.reports[0].report' /tmp/v.json | awk 'NR==1 && $0=="---"{f=1;next} f && /^---$/{exit} f' \
    | grep -E '^(decision|confidence|review_status):'
review_status: complete
decision: keep_open
confidence: high
```

The JSON report object carries only `item_number`, `artifact_path`, `report` — no `decision` key.

**The report extraction:**

```console
$ jq -r '.reports[0].report // empty' /tmp/v.json | awk '…strip frontmatter…' > /tmp/report.md
$ echo "chars=$(wc -c < /tmp/report.md)"
chars=12521
```

**The body hand-off**, with `--body-file` on the pinned image, using a deliberately invalid key so no
model call is billed:

```console
$ … clawsweeper-review                      → review_additional_prompt_chars: 483
$ … clawsweeper-review --body-file /body.md → review_additional_prompt_chars: 867
```

**The findings count** comes from the engine's OWN structured record, not from counting markdown
bullets — the report embeds `review_record:` as JSON and `decision.reviewFindings` is the authoritative
list:

```console
$ jq -r '.reports[0].report' /tmp/v.json | awk '/^review_record: /{sub(/^review_record: /,""); print; exit}' > /tmp/rec.json
$ jq -r '.decision.reviewFindings | length' /tmp/rec.json
2
```

`findings` starts EMPTY (not `0`), so an unparsable record can never read as a clean review; the label
rule requires `review_status == complete` AND `findings == "0"` AND `decision == keep_open` before it
claims `clawsweeper:reviewed`. Everything else — findings, a non-`keep_open` decision, an incomplete
review, an unparsed record — is `needs-attention`. It fails toward a human look, never toward a claim
that was not earned.

**The frontmatter extractor** is tested both ways: a report beginning with `---` yields its frontmatter;
one that does not yields nothing, rather than "everything after line 1".

The end-to-end run is the caller (`crabbox#16`) once this merges.

## Round-1 findings on this PR

1. **The findings count was unvalidated markdown counting.** Replaced with the engine's structured
   `review_record.decision.reviewFindings` (measured: 2), failing safe to `needs-attention` when the
   record cannot be parsed.
2. **The label step could describe an infra failure as a review finding.** It is now gated on
   `steps.comment.outcome == 'success'`.
3. **`findings=0` initialisation defeated the fail-safe** — now empty, so only a successful parse can
   claim "no findings".
4. **The parsed `decision` was unused** — it now participates in the rule: `reviewed` requires
   `decision == keep_open`.
5. **Cross-repo fetch authorization** — the prepare step already sets `GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}`
   (it is visible in that step's `env:`), and both `opencharly/opencharly` and this repo are PUBLIC, so a
   repo-scoped token reads the content API. The fetch is still first exercised end to end by the caller's
   live run, and this body says so.
