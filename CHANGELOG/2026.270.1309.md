The red required check therefore had no explanation. The tail is now bounded three ways — line count (`tail -n 40`), per-line length (`cut -c1-2000`), and total (`tail -c 16000`).

The org pin (`v2026.267.0045`) welds `plugin-review@v2026.266.1944`, which reads ONLY `embeddedPrompt` + `AI_REVIEW_PROMPT_EXTRA`; it never reads `REVIEW_PROMPT_PATH` (0 hits in its own source) and never reads `AI_REVIEW_PROMPT`. Its embedded `prompt.md` is the FULL rulebook. Therefore:

- Removing `REVIEW_PROMPT_PATH` changes **nothing** for the currently-pinned engine — it was already vestigial. The engine bump the deleted comment named (`opencharly/charly#626`, the embedded-prompt engine, **merged**) is already inside the org pin; this is exactly the "dropped in the same change that bumps the pin" the comment asked for.
- Dropping the `AI_REVIEW_PROMPT_EXTRA` forwarding loses nothing: the org variable is unset, and the pinned engine's full rulebook is embedded.
- Forwarding `AI_REVIEW_PROMPT` is ignored by the current engine and read by the generic engine after the weld; the org variable is already SET.

There is therefore **no window in which the gate lacks its rulebook**. This PR lands first; the generic engine welds in afterwards and finds `AI_REVIEW_PROMPT` already forwarded and set.
