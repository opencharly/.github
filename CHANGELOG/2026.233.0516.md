## fix(ci): replace the per-repo inline auto-merge engine with a single reusable workflow

### The change

The org-wide auto-merge engine previously existed as a 353-line inline `run:` block
in `.github/workflows/auto-merge.yml`, copy-pasted identically into all 14 opencharly
repos.  This PR replaces that pattern with a **single reusable workflow**
(`.github/workflows/auto-merge-reusable.yml`, `workflow_call`) called by a ~20-line
dispatcher in each target repo.

The engine itself is rewritten to use proper GitHub Action mechanisms:

- **`actions/github-script@v7` (Octokit)** for ALL GitHub API interactions — finding
  the PR, checking state, updating the body, listing check-runs, creating tags.
  No raw `gh api` calls, no fragile JSON-grep pipelines.
- **`github.graphql` (GraphQL mutation `enablePullRequestAutoMerge`)** to enable
  native auto-merge instead of the gh CLI `--auto` flag.
- **`actions.createWorkflowDispatch`** to trigger the validator on the finalized
  head, replacing the fragile "find the action_required run and re-run it" dance.
- **Native auto-merge delegates ALL check-waiting to GitHub** — the engine no longer
  polls check-runs in bash; GitHub's native auto-merge waits for every required status check.

Bugs fixed in the engine:
1. **Body-append ordering** — the finalization note is now inserted BEFORE the
   `## Attribution` section, so the `Assisted-by:` attribution footer remains
   the last line in the PR body (A1 compliance).
2. **Already-finalized guard** — the marker check uses the file's own basename
   stamp (prose cannot collide with it).

New file structure:

| File | Purpose |
|---|---|
| `.github/workflows/auto-merge-reusable.yml` | The canonical engine — ONE file for the whole org |
| `.github/workflows/auto-merge.yml` | Dispatcher for this repo (calls the reusable engine) |
| `org-wide-auto-merge-dispatcher.yml` | Template file to install in every other target repo |
| `.github/workflows/pr-validator.yml` | Now supports `workflow_call` (for the same dispatcher pattern) |

Deleted: `.github/scripts/auto-merge-harness.sh`, `.github/scripts/auto-merge-runblock.sh`
— no longer needed; the engine has no de-templated copy.

### Change class

CI/workflow — workflow definitions (`auto-merge-reusable.yml`, `auto-merge.yml`,
`pr-validator.yml`), the dispatcher template, and one CHANGELOG entry. No code,
no candies, no runtime packaging.

### How tested

- The new engine uses the same CHANGELOG finalization logic (git mv + sed H1 rewrite
  + marker) that has been proven live on distro-arch#17 and charly#363.
- The Octokit-based tag creation mirrors the exact tag scheme (normal repos:
  `v<YYYY.DDD.HHMM>`; SDK: `v0.<YYYYDDD>.<HHMM stripped>`).
- This PR's own landing is the live proof: the **old** inline engine (still on `main`)
  processes this PR through the existing auto-merge workflow. Once merged, all future
  PRs use the new reusable engine.
- The closed-PR path (tag-only, no finalization, no auto-merge) is guarded by
  `if: steps.pr.outputs.state == 'open'` on every subsequent step, so a merged
  PR that arrives via the `workflow_run` trigger is safely tagged without attempting
  auto-merge.
