## fix: check workflow_run conclusion at runtime in approve workflow

### The change

The approve-validator-runs workflow's job used
`if: github.event.workflow_run.conclusion == 'action_required'`. This
evaluated to false in the event payload, so the job was skipped and
GITHUB_TOKEN-created runs stayed in approval-required state.

The check now happens at runtime in the script: the job always runs,
logs the conclusion, and only approves when it is `action_required`.

### Why

GITHUB_TOKEN pushes (the CHANGELOG rename) create
`pull_request: synchronize` runs in approval-required state. The
approve API (`POST /actions/runs/{id}/approve`) resolves them, but
only if the job actually runs. The `if:` condition prevented it.

### How tested

The approve API was verified live: it approved run 32503192154
(action_required from a GITHUB_TOKEN push), which then ran and
completed SUCCESS. This PR's landing will confirm the runtime check
works end-to-end.
