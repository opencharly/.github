# 2026.269.1824 — feat(ci)!: replace the blocked rerun-listener distributor with a capability-free org-wide sweep

## Summary

Replace the **blocked** per-repo rerun-listener distributor (dotgithub#121) with
a **capability-free org-wide sweep** that needs no per-repo file and no
`workflows: write`.

The diff:
- **`.github/workflows/rerun.yml`** (new; schedule + dispatch) — the ONE org-wide
  owner that does both halves:
  - `ensure-label` — creates the `rerun` label in every repo (`issues: write`).
  - `sweep` — finds open `rerun`-labeled PRs org-wide and re-runs each one's
    failed validator run, then removes the label (`actions: write` +
    `pull-requests: write`).
- **`scripts/ensure-rerun-label.sh`** (+ `_test.sh`) — idempotent label ensure.
- **`scripts/sweep-rerun.sh`** (+ `_test.sh`) — the sweep.
- **Removed (R5)** the distributor files
  (`org-wide-rerun-listener.yml`, `scripts/distribute-rerun-listener{,_test}.sh`,
  `.github/workflows/distribute-rerun-listener.yml`).
- **`README.md`** section + **`validator-harness.yml`** wiring updated.

### RCA (8-step, R1) — MEASURED

**Unexpected.** dotgithub#121's distributor aborted on dispatch:

```
FATAL: the token cannot write workflow files (403 on .github).
```

**Mechanism.** Installing `.github/workflows/rerun-listener.yml` org-wide needs a
GitHub App with **`workflows: write`**. The `charly-auto-merge` App's permissions
are `actions, contents, deployments, issues, merge_queues, metadata, packages,
pages, pull_requests, repository_custom_properties` — **no `workflows`**. Per the
GitHub docs a GitHub App's permission set can only be changed in its **settings
UI** — there is **no API** to grant it; and a direct workflow-file PUT with the
org-owner token returns `409 Required workflow … is not satisfied` (only the App
is a ruleset bypass actor).

### Fix — remove the dependency entirely

The App **does** have `issues: write`, `actions: write`, `pull-requests: write`.
The channel is rebuilt from those: a **label** (created org-wide via the issues
API) is the operator's signal; a **scheduled sweep** in `.github` finds labeled
PRs and re-runs each one's failed validator run. No per-repo file, no
`workflows: write`, no capability escalation.
