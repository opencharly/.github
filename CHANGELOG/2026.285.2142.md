# 2026.285.2142 — fix(detector): read the non-resolving required check and the DIRTY half

## Summary

The org's stalled-mergeability reader covered **one** measured shape and said so in its own scope note: auto-merge armed + a `BEHIND` head (`opencharly/.github#175`). Three shapes are measured now, each on a live stall:

1. **ARMED + BEHIND** (#175) — unchanged.
2. **ARMED + DIRTY** (#175 comment `6084457430`) — strictly worse and needing its own handling: `gh pr update-branch` CANNOT resolve a conflict, so an armed conflicted PR waits forever with no signal at all (measured on `charly#432`, ~30 h).
3. **THE REQUIRED CHECK NEVER RESOLVED** (#186) — a superseded validator run leaves `validate / validate` `CANCELLED`. Arming happens **inside** the validator run — the run that was cancelled — so the PR sits `BLOCKED` with `autoMergeRequest == null` and reads as *queued*: nothing re-dispatches it and no check ever concludes. Measured on this repo's own `#185` (`armed = Y` *and* the required check `CANCELLED`).

Three properties of the third class are deliberate:

- It reads **every run of the required context on the head**, not only the newest. A branch protection rule requires *every* same-name run to pass, so an older `CANCELLED` beside a newer `SUCCESS` keeps a PR blocked forever (the POISON pair); a newest-only filter would miss exactly that.
- `FAILURE` is **excluded**. A red required check is a verdict, and a red PR gets read; this alarm exists for the quiet ones.
- Armed or unarmed does not matter here, because the filing instance sat unarmed — that is the whole point of the shape.

`report_stalled` now prints the remedy **per class**, and for the third class it carries the caveat the issue itself measured: the REST re-run is a **fresh review** that replaces the verdict (`charly#871`: a re-run turned a `PASS` into a `BLOCK` carrying a finding the first run had not raised). The alarm line reads *"Never re-dispatch a head you have not read and fixed."*

**Scope, stated so nobody over-trusts it** (the sentence declaring the cancelled shape out of coverage is deleted): an *unarmed* `BEHIND`/`DIRTY` head, and a head carrying **no** run of the required context at all — the fork case, `#179`, where no org gate applies — are **not** selected. Deciding those needs the ruleset scope derivation in `scripts/lib-org.sh` `discover_excludes`, which this reader deliberately does not read. Under-reporting is the honest failure mode: a detector that cries wolf on ~16 forks is switched off, and then it detects nothing.

`scripts/governance-claims.tsv` gains the `stall_shapes` claim (4 rows): the canonical phrase `REQUIRED CHECK NEVER RESOLVED` must be present in **both** the rule's carrier (the script) and its alarm surface (the workflow), and the retired wording (`not covered`) must not return to either — that sentence is how shape 3 stayed invisible.

This change does not touch the org gate, the ruleset, or the PR template; it strengthens the **observer** of the landing contract, relaxing nothing.

Closes #186.
