# 2026.280.0830 — fix(validator): grant the `issues` scope so a PRIVATE repo can be validated (#173)

## Summary

Grant the **`issues` scope** to the org-wide `charly/pr-validator` gate so it can validate a PR in a **private** repository.

The review reads the PR **body** via the issues API (`GET /repos/{owner}/{repo}/issues/{n}`) and posts its verdict/INCONCLUSIVE notice as a PR comment — both are the `issues` scope. The `permissions:` block declared `contents`/`pull-requests`/`checks` but **no `issues`**. For a **public** repo the raw body is readable unauthenticated, so the gap is invisible; for a **private** repo the read requires the scope and 403s:

```
review: read PR body: gh: /repos/opencharly/charly-images/issues/4:
  HTTP 403: {"message":"Resource not accessible by integration"}
review_rc=1   provider_error=(empty)   provider_unanswered=false   engine_defective=false
```

`opencharly/charly-images` (created 2026-10-06) is the org's **only** private repo (450/450 others are public), and the gate is verdict-less `INCONCLUSIVE` on **every** run there (`#1`–`#4`) while the same validator returned real `PASS` verdicts on the public `charly`/`sdk`/`plugin-vm` in the same window. No private-repo PR can merge through the gate.

**Regression.** `issues: write` was present from the workflow's introduction (`.github#11`) and removed in `.github#25` — harmless while every repo was public. This restores it, and adds the R10 coverage that keeps it.

Files:
- `.github/workflows/pr-validator.yml` — add `issues: write`.
- `.github/workflows/org-wide-pr-validator-required.yml` — add `issues: write` to the CALLER (a called workflow holds only what its caller grants).
- `.github/tests/validator-gate-harness.py` — assert the scope on **both** surfaces (fails without it).

Closes #173. Unblocks `opencharly/charly-images#4`.
