## fix: bump pi-review-action to v1.0.9, pass pr-number input

### The change

Bumps `opencharly/pi-review-action` from v1.0.8 to v1.0.9 and passes
the `pr-number` input.

v1.0.9 accepts a `pr-number` input and fetches the PR via the API when
there is no `pull_request` event context (e.g. `workflow_dispatch`
re-runs). This enables the auto-merge flow to re-validate the
CHANGELOG-renamed head after the GITHUB_TOKEN push.

### Why

The CHANGELOG rename push uses GITHUB_TOKEN. Per GitHub docs,
GITHUB_TOKEN-triggered `pull_request: synchronize` events create
approval-required runs — not automatic ones. The auto-merge flow
dispatches a validator re-run via `workflow_dispatch`, but the
pi-review-action previously failed with "No pull_request context" in
that mode. v1.0.9 fixes this by fetching the PR via the API.
