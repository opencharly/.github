# 2026.265.1713 — fix(ci): fail fast on the workflows-permission 403 + document the app requirement

## Summary

RCA fix for a defect found while executing the org-wide validator cutover: the retirement workflow's `charly-auto-merge` App token holds `contents: write` (which carries the ruleset bypass for a protected-`main` commit) but **not `workflows: write`** — the distinct GitHub Apps permission required by `DELETE` on `.github/workflows/*`. Every delete on a repo where the app had not already succeeded returned `403 Resource not accessible by integration`; the script counted those as ordinary failures and churned through the whole org before aborting at the failure cap.

Changes:

- **`scripts/retire-per-repo-dispatchers.sh`** — a `403 Resource not accessible by integration` is now classified as a **PERMISSION** error and aborts the run immediately with the exact remediation (the App must hold `workflows: write` in addition to `contents: write`), instead of churning through the remaining repos. The offline test gains the 403-abort case and asserts the remediation text.
- **`.github/workflows/retire-per-repo-dispatchers.yml`** — header documents the required App permission (`contents: write` + `workflows: write`) and where to grant it.
- **`README.md`** — the bot-token section names the `workflows: write` requirement; a new section documents the org-wide required workflow (ONE org ruleset, no per-repo copy) and the one-time cutover order.

This is a follow-up to `#109` (merged), which introduced the cutover machinery.
