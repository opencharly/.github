# 2026.238.1210 — fix(tag-on-merge): create the subdir MODULE tag for plugin repos

## Summary

The candy de-submodule cutover made compiled plugin candies standalone Go
modules at `github.com/opencharly/<repo>/candy/<repo>`. Their go.mod pins
must be CLEAN CalVer tags — but tag-on-merge only created the ROOT tag
(`v2026.238.0955`), so plugin-fleet's first post-merge pin degenerated into
a proxy pseudo-version (`v0.2026237.1423-0.20260826095529-c928a5310653`)
that no git ref resolves, breaking pluginsgen's fetch
(`TestPluginsGenReproducible` on charly).

For `plugin-*` repos, ALSO create the subdir module tag
`candy/<repo>/v0.<y><doy>.<hhmm>` (SDK-style, leading-zero stripped —
semver patch cannot start with 0) at the merge commit. Root tags
(`v2026.238.0955`) remain for the runtime's repo-root fetch; the subdir
tag is the Go module version.

## How tested

- The equivalent tag was created live on opencharly/plugin-fleet
  (`candy/plugin-fleet/v0.2026238.955` at the merge commit) and verified:
  - `go list -m github.com/opencharly/plugin-fleet/candy/plugin-fleet@v0.2026238.955` resolves
  - charly's `TestPluginsGenReproducible` passes against the clean pin
- The JS mirrors the existing idempotent getRef/createRef pattern from the
  root-tag block directly above it (same API, same try/catch).
