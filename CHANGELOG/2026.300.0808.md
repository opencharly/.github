# 2026.300.0808 — fix(gate): the candy gate's activation precondition must name the LIVE blocker, not the discharged one

## Summary

The org's candy-manifest gate (`.github/workflows/candy-validate.yml`, the `candy / validate` reusable) states **one** activation precondition: *"Do NOT activate it as a required gate until `vars.CHARLY_VERSION` names a release that carries the schema-versioning removal — the pre-removal pin still requires the retired stamp and would fail the very PRs this leg unblocks."* The same claim is repeated in `README.md`.

**That blocker is DISCHARGED.** `opencharly/.github#162` moved the org knob from `v2026.271.0950` to `v2026.278.0912`, past the `2026.275.2112` stamp retirement, and a stamp-less manifest now validates green under that release. So the header, read at its word, **licenses activating the gate** — and activating it today would redden every repo that declares the routing-only `skill:` shape, for a reason the header does not name: the knob's engine still **rejects** that shape.

This change corrects the two prose surfaces to name the **LIVE** condition and to mark the discharged one as discharged, and **enforces** the correction with four new rows in the org's cross-surface claims gate.
