# 2026.251.2000 — gate: switch the org PR validator to the charly/plugin-review engine (action-review cutover)

## Summary

The org-wide reusable PR validator (`charly/pr-validator`) switches from the `opencharly/pi-review-action` step to the **charly-native gate** (the action-review cutover): the plugin-review charly plugin, welded into the charly release, driven by `charly review --plan review-plan`.

What changes (2 touch points in this one file):

1. **The review step block** — replaces `uses: opencharly/pi-review-action@v1.0.11` with:
   - checkout of `opencharly/action-review@main` (the org-controlled config repo; **T1**: validator instructions come from main, never from the PR under review) into `runner-config`;
   - an idempotent **Ensure charly** bootstrap: downloads `charly-linux-amd64` + `charly-plugins-linux-amd64.tar.gz` from the pinned/latest `opencharly/charly` release (the same assets the distro package repos consume), sets `CHARLY_PLUGIN_DIR`, and self-tests the welded word (`$D/bin/charly review --self-test` — absolute path: `GITHUB_PATH` applies to later steps only);
   - **Run review plan**: `charly review --plan review-plan --out /tmp/review.txt` with the same `PR_NUMBER`/`AI_REVIEW_*`/`GITHUB_TOKEN` env (inputs → vars → secrets, exactly as the dispatcher passed to the action). Which plugins/steps run lives in `review-plan.yml` — the workflow never changes for that.
2. **`runs-on`** — `ubuntu-latest` by default, `vars.REVIEW_RUNNER_LABEL` opt-in (the standard-runner default never needs a self-hosted runner).

**Validator findings fixed in this head (2):** (1) the review step now writes `response`/`success`/`verdict` to `$GITHUB_OUTPUT` EXPLICITLY from the saved review file (heredoc `response<<REV`, grep-derived `verdict`, `success=true`) — the parse step's `steps.review.outputs.*` contract is self-contained and statically verifiable, independent of the executor's env behaviour (which also writes it); (2) the auto-merge loop's `*head branch is behind*` case pattern had the glob inside the quotes (latent pre-existing defect, now visible as the file is touched) — fixed and collapsed with the overlapping `*is behind*` alternative (shellcheck SC2221/2222 clean).

**Explicitly preserved (required-check identity + gate contract):** workflow name `charly/pr-validator`, job `validate`, all `workflow_call` inputs, `permissions`, the `Parse verdict`/`Gate (BLOCK)`/`Gate (ambiguous)`/`Enable auto-merge` steps, and the no-concurrency note (#163). Verified the executable contract is identical: the parse step consumes `steps.review.outputs.response` exactly as before (the executor writes `response`/`success`/`verdict` to `$GITHUB_OUTPUT`).
