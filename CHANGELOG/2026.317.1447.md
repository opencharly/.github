# 2026.317.1447 — fix(gate): the engine pin measures the asset and names the class, not the release

## Summary

The org gate reports the wrong cause when the pinned engine cannot be fetched, and a gate
that names the wrong cause is the same defect family as a gate with no callers. This PR
makes the fetch **measure itself** and gives the gate **four named classes, each with its
own remedy**, instead of one that blames the release.

tree, and the measurement inverts the rest:

So the defect is not the pin. It is that the class could not say *what* failed, and named
`"the release is published but its assets could not be downloaded (a partial upload)"` — a
false cause, with a remedy ("serve the pinned release") that was already true.

### What changed

* **`Ensure charly` measures instead of trusting** (`pr-validator.yml`): each asset is fetched
  **without `-f`** (the status and the body *are* the measurement) and the bytes are judged —
  HTTP status, size, and the first four **magic bytes** (`7f454c46` ELF for the binary,
  `1f8b08` gzip for the plugin bundle). A 200 carrying a gateway page is not an engine, so a
  200 alone is not the check. The second asset is fetched only when the first is good, so a
  failing path does not spend a second 100 MB round trip. The release's own state is measured
  separately over the API (`published` / `draft` / `absent` / `no-tag`) and emitted as
  `release_state`, `asset_state`, `asset_url`, `asset_http`, `asset_bytes`, `asset_form` —
  replacing the single `pin_class`.
* **The gate classifies FOUR ways, with the URL and the status in the class line**
  (`pr-validator.yml`, `Gate (inconclusive)`), each with its own remedy:
  1. `engine pin unresolvable — the pin names no existing tag: <tag> is absent …` — a dead
     tag; remedy: fix the pin (the class `charly#723` owns).
  2. `engine pin unresolvable — the tag <tag> has no PUBLIC release to serve its assets
     (state: <release_state>)` — a tag without a published release; same owner.
  3. `asset unreachable — <url> answered HTTP <status> (<n> bytes, <form>)` — the **download
     path** failed; neither the pin nor the release is wrong, and the remedy is a **RE-RUN**,
     explicitly *not* a pin move. It also names the API-route check as the operator's
     diagnostic and says why the gate does **not** fall back to it (a silent second fetch
     would hide the class, R3).
  4. `asset absent — the published release <tag> does not serve <url> (HTTP <4xx>)` — the
     release's own defect; remedy: re-upload, or move the pin.
  and the `else` arm they fall through to, `asset unreadable — <url> answered HTTP <status>
  with <n> bytes that are <form>` — a 200 that is not the asset (the gateway-page case). The
  asset probe's `asset_state` vocabulary is exactly `endpoint-failed` / `absent` /
  `wrong-body`, and the coverage asserts all of it.
* **Coverage that can fail** — `scripts/engine-pin-asset_test.sh`: six discriminations
  (good pair; 504 gateway page; **200 with an HTML body**; 404 on a published release; dead
  tag; tarball-only 504), each asserting both the machine outputs **and** the comment body the
  gate would post, plus **three negative controls** that turn the coverage RED.
* **A live harness** — `scripts/proof-engine-pin.sh` replaces `scripts/proof-unresolvable-pin.sh`
  (retired) and runs the same shipped step text live and replayed, using the shared extractor
  in `lib-org.sh` (the retired script carried its own copy — an R2 duplication removed here).
  It carries **no tag literal**: the default pair is resolved at run time from the org pin and
  the release before it, because a tag written into a script is exactly the rot-prone value
  this change is about. This round's run of it proves that property behaviourally — it chose
  `v2026.317.0159` as the "other" tag, which no version of this branch ever wrote down.
* **The rule protected from drifting** — two `scripts/governance-claims.tsv` rows: `require
  "asset unreachable"` on the validator workflow (which also anchors the path) and `forbid
  pin_class` (the retired output).
* `AGENTS.md` / `README.md` document the probe and the four classes.

**This PR changes no review criterion, no model setting, no timeout and no auto-close
threshold.** The class stays **INFRA** and stays excluded from
`AI_REVIEW_AUTO_CLOSE_AFTER`; the gate still fails closed (`exit 3`, required check RED,
unreviewed code never merges); there is still **no in-job retry** (R3).
