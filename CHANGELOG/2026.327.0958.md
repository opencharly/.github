# 2026.327.0958 — feat(labels): add the generic org-wide issue taxonomy

## Summary

Add the org-wide issue taxonomy: every issue carries **exactly one `category:` and one `type:`** from two closed sets (12 labels total). There are no severity/priority/size/status/ownership labels and **no fallback value**: an under-specified issue is improved or split, never guessed.

- **Generic, no repo→category defaults.** `labels/category-rules.json` holds only generic path rules and action keywords. The classifier reads the paths the issue names, then the generic action keywords; it never reads the repository name. **Every category is available in every repository**, so a new or future repo needs no rule change.
- **One tool, one classifier.** `scripts/labels.sh` owns `sync`, `audit`, `classify`, `apply`, `retire`, `render`, `verify-close`, `sample`, `explain`. `api_error_class` is the ONE 404/quota/permission classifier in `scripts/lib-org.sh`; `backfill-missing-tags.sh` delegates to it.
- **Org-level placement.** The taxonomy, rules, workflows, the org issue form, sync/audit and claims live once in `opencharly/.github`. Labels are per-repo storage only; the org `label-sync` workflow provisions the same 12 labels everywhere and `bootstrap-repo-main.yml` syncs a new repo. No repository ships a label config.
- **The org issue form** (`.github/ISSUE_TEMPLATE/issue.yml`) is generated by `render`: four required fields (Category, Type, Remedy/files, Cited decision/rule), `labels: []`, inherited by every repository without its own template.
- **Held-out validation.** The valid set **R** is disjoint from A–O (0 exact-line overlap; used 318 = 298 + 20) and passed the fresh generic reader: **0 splits, 1 remedy-less under-specified**, every category usable in every repository.

### R1 finding fixed in this change (the sampler id-form bug)

The first live draws compared a short `repo#num` candidate against a used set stored as `org/repo#num`, so a used issue was never excluded. Samples **P and Q were duplicates** of A–O (19 and 8 ids) and are **not held-out rounds**; they are not recorded.

- **Root cause:** the sampler built `id="$repo#$inum"` while `cold-reader-used.json` holds `org/repo#num`.
- **Missed control:** the offline test's used fixture used the short form, so the live full form was never exercised.
- **Blast radius:** P and Q invalid as held-out sets; no repository state was changed.
- **Root fix:** the sampler normalizes to `org/repo#num`; the test uses a full-form used fixture; `sample --from <fixture> --record` records the fixture that was actually read; the used set is rebuilt from A–O + R (318).
