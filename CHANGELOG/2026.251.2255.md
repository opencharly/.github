# 2026.251.2255 — fix(gate): review text never through GITHUB_OUTPUT

## Summary
The reusable pr-validator workflow exported the engine's full review text through a `$GITHUB_OUTPUT` heredoc (`response<<REV`). The engine's review text is markdown whose step sections are `###`-led lines; GitHub's file-command parser rejects such a line inside a heredoc value with `Invalid format '### [step: review]'` — live evidence: distro-omarchy#49's validate job (34s failure before the gate ran).

Fix: the review step no longer exports the response; the Parse verdict step reads `/tmp/review.txt` directly (same job, same filesystem). Only scalar `verdict`/`success` outputs remain.

## How tested
- Validated the workflow YAML (parse-able, no remaining `steps.review.outputs.response` consumers).
- Behavior: distro-omarchy#49 re-runs green after this merges to main (the reusable workflow is read at dispatch time).

## Rulebook compliance
R1: the failure was RCA'd to the GITHUB_OUTPUT heredoc parser rejecting `###`-led lines inside the value; the fix removes the fragile channel entirely. PR-only landing through the org gate.

Fix — org gate workflow; verification gate: the org validator on this PR; attribution tier: analysed on a live system (live failure reproduced + fix mechanically verified; full re-run lands after merge).
