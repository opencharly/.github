# 2026.307.2007 — docs(ci): the image-build caller triggers on workflow_run, not push:tags

## Summary

**Head `1054e548306f9511a93a12c57dcd2dbdace6a530` (tree `5ba7a5ba`), base `c2a720d` — 1 file, +44/−4. Comment-only.**

`image-build.yml` is the org's ONE reusable image build/publish workflow, and its INVOCATION block is the template every `pod-crabbox*` repo copies. That block prescribed:

```yaml
on:
  push:
    tags: ['v*']
```

**That trigger cannot fire for a tag this org creates.** `tag-on-merge` mints the CalVer tag through the REST API (`git.createRef`), which emits no push event, so a `push: tags` listener never sees it. This is not an inference: `opencharly/pod-crabbox` merged (#2, `1b9a9c06` `1b9a9c061755f69f3d98310b3f3896b8184ecd49`), `tag-on-merge` minted `v2026.307.1759` on exactly that commit, the caller declared `push: tags` — and **zero `image` runs were created**. Every `image` run on record was `pull_request` (`opencharly/.github#277`).

The remedy is already the org's proven pattern, and `charly/.github/workflows/release-binary.yml` documents it in its own header: chain off `tag-on-merge` **completion**, "the ONE trigger whose event delivery is proven".

This PR replaces the block with the caller shape that is measured working, and states the mechanism and the evidence inline so the next repos inherit a pattern that fires.

**What is NOT changed:** the workflow's `on: workflow_call`, its `box`/`push`/`tag` inputs, `permissions`, and every job. The diff is inside the header comment only.
