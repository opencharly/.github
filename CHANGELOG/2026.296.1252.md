# 2026.296.1252 — feat(ci): a workflow that can actually distribute the tag-on-merge caller

## Summary

Adds `.github/workflows/reconcile-tag-on-merge-callers.yml` — a `workflow_dispatch` job that
mints the `charly-auto-merge` App token and runs
`scripts/reconcile-tag-on-merge-callers.sh`, so the canonical tag-on-merge caller can actually
be distributed across the org. The script gains an optional `RECONCILE_REPOS` allow-list.

## Why this exists — the blocking measurement

`#239` changed the canonical template's `runs-on` to `${{ vars.CI_RUNNER_LABEL || 'ubuntu-latest' }}`.
That template is the file `scripts/reconcile-tag-on-merge-callers.sh` copies into every repo that
already has a caller. Running the script directly against the org does not work: every write is
refused by the org ruleset.

```console
$ gh api -X PUT repos/opencharly/spec/contents/.github/workflows/tag-on-merge.yml \
    -f message="ci: reconcile the tag-on-merge caller ..." -f content=@<(base64 -w0 canonical) -f sha=f5030888d197...
gh: Required workflow 'charly/pr-validator, charly/pr-validator' is not satisfied
Required status check "validate / validate" is expected. (HTTP 409)
```

Same result on `marketplace` and `plugin-task`; nothing was written (all three files still sit at
their original blob `f5030888d197…`).

The ruleset's only bypass actor is one Integration:

```console
$ gh api repos/opencharly/spec/rulesets/23827016 --jq .bypass_actors
[{"actor_id":4675576,"actor_type":"Integration","bypass_mode":"always"}]
$ gh api /orgs/opencharly/installations -q '.installations[] | "\(.app_id) \(.app_slug)"'
85455 cloudflare-workers-and-pages
1144995 chatgpt-codex-connector
4675576 charly-auto-merge
```

That is deliberate policy — no human token may bypass `main` protection — so the sweep has to run
as the App. This repository already does exactly that twice
(`retire-per-repo-dispatchers.yml`, `strip-config-version.yml`); the reconcile script was written
for a bot-token runner and had no wrapper. This is that wrapper, copying their two-step shape and
their two required App permissions (`contents: write` for the write and the bypass, `workflows:
write` because GitHub refuses any create/update under `.github/workflows/` without it).

## The allow-list, and why the sweep is piloted

Distribution is **one commit on each repo's `main`** — 419 repos today, all of them drifted
(`verify` on the final tree: `repos examined: 419`, `prose-drifted: 419`, `both: 412`). So the
script takes an optional `RECONCILE_REPOS` (space- or comma-separated names; empty means every
discovered repo), surfaced as the workflow's `repos` input. A pilot names a few, they are read
back, and only then does an unfiltered dispatch touch the rest. The `mode` input defaults to
`verify`, which writes nothing.

`select_repos` is a pure function and is unit-tested: empty and whitespace-only lists pass
everything, a name keeps only itself, comma and space forms both work, and the output keeps the
**arrival** order rather than the order the names were requested in.

## How tested

```console
$ for t in scripts/*_test.sh; do bash "$t"; done
bootstrap-repo-main_test: all assertions passed
org-ruleset_test: all assertions passed (apply/verify/abort)
reconcile-tag-on-merge-callers_test: 17 passed, 0 failed
retire-per-repo-candy-gates_test: all assertions passed
retire-per-repo-dispatchers_test: all assertions passed
strip-config-version_test: all assertions passed
```

The six new assertions are the allow-list's; without `select_repos` the test file fails on the
first one, so the new coverage cannot pass by accident.

That test file was also **never run by any gate** — `workflow-checks.yml` ran every other
owner-script test but not this one. Round 1 adds it, so the assertions above (and the script's
existing two dimensions) are now gated on every PR instead of only when someone remembers.

The workflow's own proof is its first dispatch. That is a `workflow_dispatch`, so it cannot run
on this PR — the first run after merge is `mode=verify` (read-only) and its report is the
measurement of the org's drift.
