# 2026.287.2122 — fix(tag-on-merge): size the readiness bound to the measured merge latency, and add a schedule backstop

## Summary

**The tag-on-merge caller's readiness probe was bounded shorter than the auto-merge latency it exists to cover, so a merged PR could be left untagged by a run that reported `success`.**

Measured on `charly-registry#12` (merge `bf9b329e2d`, 21:01:59Z):

```
20:54:18Z  pull_request  charly/pr-validator  completed/success  45315ad2   ← the PASS
20:55:54Z  workflow_run  tag-on-merge         completed/SUCCESS  (head 80754ff2)
21:01:59Z  #12 merges
```

The caller fired 96 s after the PASS and **concluded `success` while tagging nothing**: its probe is bounded at `Date.now() + 5 * 60 * 1000`, the PASS→merge gap was **7m 41s**, so the loop expired and the single-shot sweep that follows ran *before* the merge existed. `#10`'s gap was **3m 03s** and it tagged — one repo, one mechanism, opposite outcomes. No tag and no `CHANGELOG/2026.287.21xx.md` exist for `#12`.

**The change, all in the one file the bootstrap installs (`.github/workflows/tag-on-merge-dispatcher.yml`, `scripts/bootstrap-repo-main.sh:73`):**

1. **Bound raised to 20 minutes**, with the measured numbers written into the file so the next reader sees why it is that number.
2. **A coarse `schedule: */30` backstop**, so a merge the primary path misses is recovered by the workflow itself instead of waiting for **the next validator completion in that same repo** — which on a quiet repo can be days, and is why `#12` is still untagged. Cron stays deliberately **not** the primary trigger (best-effort delivery, measured 21-44 min gaps); it is a non-zero recovery path where there was none.
3. **Both jobs' `if:` accept `schedule`**, and the probe's non-`workflow_run` message names the event instead of hard-coding `push` — without the `if:` change the backstop would run the wait job and then skip the tag job entirely.
4. **The header's "no cron" claim is corrected** in the same edit, because it is now false.

**Scope stated, not implied:** the *installed* callers in existing repos are bootstrap-time copies, so this template change reaches **future installs**; bringing the existing copies forward is `opencharly/.github#192`'s surface (`R5: the per-repo tag-on-merge callers still run actions/github-script@…`) and is not attempted here. No add-only backfill for `#12` is included in this PR either: the operator directed a root-cause fix first.
